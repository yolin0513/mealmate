# SPEC：排菜葷素比例 —— 讓「不可分流的純葷菜」在有素食成員的家庭也排得進去

- 日期：2026-09-16
- 規劃：Fable 5.1（統籌 Session）。實作：MealMate 的 Opus 5 Session。
- 狀態：**草案，等 Yolin 拍板 §10 的待確認清單後才實作。** 拍板前不動任何程式。
- 對應需求（Yolin 原話）：「午餐、晚餐在『素食有 2 道菜以上』的情況下，可以有幾道是葷食；不然像『滷雞腳』這類無法分流（不能一鍋兩吃、只有葷版）的葷菜永遠排不進去。」

---

## 0. 一句話

家裡**同時有吃葷、吃素的人**時，午晚餐在**素食成員仍吃得到足夠道數**的前提下，一週有幾餐在「第二道配菜」的位置改排一道**只有吃葷的人吃的純葷菜**（沿用現有「加菜／僅葷食成員」機制），讓 41 道純葷主菜（滷雞腳這類使用者自訂的也算）從「永遠排不到」變成「照配額輪到」。素食保障不降、全葷與全素家庭行為不變。

---

## 1. 現況（讀 `js/planner.js`、`docs/PLAN.md`、`docs/STATUS.md` 後的事實）

### 1.1 餐次組成與素食保障

| 常數 | 值 | 位置 |
|---|---|---|
| `MEAL_ROLES.lunch` | `['main','side','side','staple']`（4 格） | `js/planner.js` |
| `MEAL_ROLES.dinner` | `['main','side','side','soup','staple']`（5 格） | 同上 |
| `VEG_MIN_DISHES` | `3`：有素食成員時，每個午晚餐**每位素食成員都吃得到**的道數下限（**含主食**；主菜本身含主食如炒米粉時，被略過的主食格**不算**） | 同上，`doctest` 釘住 = 3 |

### 1.2 純葷菜（`vegMode === 'meatOnly'`）為什麼排不進去

1. `hardBlock()`：有素食成員時，一般位置的每道菜都要通過每位素食成員的 `versionFor() !== null`，純葷菜一律被擋（代碼 `diet:<名字>`）。
2. `generateWeek()`：家裡有吃葷的人時主菜硬性要求「葷」（`requireMeaty`），但可分流的主菜也算葷 —— 池子有 37 道可分流主菜，所以主菜幾乎每餐都是可分流的。
3. 唯一讓純葷菜進來的「加菜」位置（最後一道配菜格、`extraMeat: true`、畫面標「僅葷食成員」）**只在兩種情況開**：主菜排不到葷（`!mainMeaty`，真實池子幾乎不會發生），或使用者勾了純葷菜的「本週想吃」（v0.19.0）。
4. 加菜放之前會算 `vegDishesAfter() >= VEG_MIN_DISHES`，這條是對的、要保留。

### 1.3 量出來的結果（真實池子、6 個種子、`shoppingDays [3,6]`）

| 家庭 | 純葷主菜／週 | 可分流主菜／週 | 魚貝主菜／週 | 紅肉主菜／週 | 加菜／週 | 素食成員每餐最少吃到 |
|---|---|---|---|---|---|---|
| 全葷 3 人 | 7.8 | 6.2 | 7.7 | 4.8 | 0 | — |
| 爸葷＋媽蛋奶素 | **0** | 14.0 | 5.5 | 5.0 | 0 | 3 道 |
| 爸葷＋姊全素 | **0** | 14.0 | 8.0 | **8.0**（配額 5） | 0 | 3 道 |

池子結構：純葷主菜 41 道（魚 13、雞 6、豬 6、牛 4、蛋＋豬 3…；時間 ≤ 40 分的 34 道、油炸 2 道）；可分流主菜 37 道（豬 15、雞 8、蝦貝 5、牛 4、魚 1…）。
**混合家庭 14 個午晚餐的主菜 100% 落在 37 道可分流主菜裡**：紅肉壓不到配額（STATUS 已記為「池子的結構問題」）、雞與魚的純葷菜整批看不到、使用者自己加的滷雞腳除非勾「本週想吃」否則永遠不出現。這正是 Yolin 講的問題。

## 2. 目標與非目標

**目標**
1. 混合家庭（≥1 位 `omni` 且 ≥1 位非 `omni`）的午晚餐，能按**使用者可調的一週配額**排進純葷菜。
2. 素食成員的保障**一道都不少於現在**（每餐仍 ≥ `VEG_MIN_DISHES`）。
3. 全葷家庭、全素家庭、沒有家人、早餐：**行為完全不變**。
4. 一切照本 App 的慣例：純函式、固定種子固定結果、理由只講事實、畫面明講排了什麼、禁用詞零出現。

**非目標（這一版不做）**
- 純葷菜佔**主菜位置**（素食成員會沒有主菜，見 §10 Q4）。
- 純葷湯（8 道）進晚餐的湯格（§10 Q7，建議第二階段）。
- 全葷家庭「一餐兩道肉」。
- 依素食成員的蛋白質來源另做保障（豆製品／蛋）。
- 改 `MEAL_ROLES`、改 `VEG_MIN_DISHES` 的值。

## 3. 名詞定義（規格與程式碼都用這幾個詞）

| 詞 | 定義 |
|---|---|
| **混合家庭** `mixedHome` | `ctx.vegetarians.length > 0 && ctx.hasOmni`。注意 `hasOmni` 在**沒有家人**時也是 true，但那時 `vegetarians` 是空的，所以不算混合家庭。 |
| **素食成員吃得到的道數** | 這一餐裡，**每位**素食成員 `versionFor(recipe, m.diet) !== null` 的道數（可分流的吃素版也算、主食算、被略過的主食格不算）—— 就是現有 `vegDishesAfter()` 算的東西。 |
| **純葷加菜** | 現有 `extraMeat: true` 的 item：`role: 'main'`、放在該餐**最後一道配菜的位置**（`lastSidePos`）、只收 `vegMode === 'meatOnly'`，畫面標「加菜」＋「僅葷食成員」。 |
| **葷食保障加菜** | 現有行為：主菜排不到葷時放的純葷加菜（不動、不算配額）。 |
| **本週想吃加菜** | 現有行為：勾了純葷菜的「本週想吃」走加菜位置（不動，但**算進配額**，見 R6）。 |
| **配額加菜** | 本規格新增：按一週配額主動放的純葷加菜。 |

## 4. 規則（建議版；Q 編號對應 §10 待確認）

### R1 觸發條件
- 只在**混合家庭**開（Q5）。全葷家庭純葷菜本來就直接當主菜，不需要；全素家庭永遠不放 `meatOnly`（現有紅線）。
- 只在午餐、晚餐；早餐不套用（沿用「早餐不要求葷」的決定）。
- 那一格沒有被鎖住的菜佔著（鎖住的優先，沿用現況）。

### R2 位置
- 沿用加菜位置：**該餐最後一道配菜的位置**（午餐 pos 2、晚餐 pos 2）。主菜位置**維持**「素食成員吃得到」（可分流或素），素食成員永遠有自己的主菜（Q4）。
- 所以配額加菜是「**用一道配菜換一道純葷主菜**」，那一餐的道數不變：午餐仍 4 道、晚餐仍 5 道。

### R3 素食保障（不變、而且是唯一的硬門檻）
- 放配額加菜之前**先算** `vegDishesAfter(extra, pos) >= VEG_MIN_DISHES`（＝3，含主食）。算不到就**不放**，這一格照常排配菜。
- 換算成 Yolin 的說法：素食成員那一餐至少**「2 道菜＋主食」**（午餐：主菜素版＋1 配菜＋飯；晚餐：主菜素版＋1 配菜＋湯＋飯）。這就是「素食有 2 道菜以上」的精確版本（Q1）。
- 主菜含主食（炒米粉、螞蟻上樹）的午餐：素食成員只剩「炒米粉＋1 配菜」＝2 < 3 → **不放**；晚餐多一道湯 → 放得下。這是現有算法自然得出的結果，照舊。

### R4 每餐上限
- 一餐**最多 1 道**純葷加菜（含本週想吃加菜、葷食保障加菜）（Q2）。位置只有一格，程式上自然成立；規格明寫是為了 Q7 若日後開放葷湯時有依據。

### R5 一週配額與分散
- 新設定 `meatExtraLevel`（`prefs.DEFAULTS`），四段：

| 值 | 一週最多幾餐 | 畫面文字 |
|---|---|---|
| `off` | 0 | 不排 |
| `low` | 2 | 少（一週 2 餐） |
| `medium` | 3 | 適中（一週 3 餐）**預設**（Q3） |
| `high` | 5 | 多（一週 5 餐） |

  常數 `export const MEAT_EXTRA_LEVELS = { off: 0, low: 2, medium: 3, high: 5 }`、`MEAT_EXTRA_LEVEL_LABELS`，放 `js/planner.js`，跟 `HEARTY_LEVELS` 同一種形狀。
- **每天最多 1 餐**（午餐或晚餐擇一），免得素食成員同一天兩餐都少一道配菜（Q3）。
- **哪幾餐開：抽籤，不是照分數。** 理由：加菜格「排配菜」還是「排純葷主菜」是兩個不同角色的 `pickForSlot`，分數不能互比；抽籤才能在固定種子下有分散、重新產生會換。
  - 候選 ＝ 這週所有 `kind === 'cook'`（沒有 prevPlan 時全部算 cook）的午晚餐。
  - 用**獨立的亂數串** `makeRng(\`${seed}|extra|${monday}\`)` 洗牌候選，依序挑，**同一天只挑一餐**，挑到 `quota` 餐為止 → `targetMeals`（Set of `${day}|${meal}`）。
  - 為什麼獨立亂數串：主亂數串 `rng` 在 `scoreSoft` 每評一道菜就消耗一次，插進去會讓**全葷家庭同種子的菜單也整個變掉**（既有固定種子 fixture 全部漂移）。獨立串則只有混合家庭的菜單會變（那本來就是目的）。
- 到那一餐時：`autoOpen = mixedHome && mainMeaty && targetMeals.has(key) && extrasPlaced < quota && !extraDays.has(day)`。開了就用現有 `pickForSlot(ctx, state, slotInfo, 'main', rng, { meatOnlyExtra: true })` 挑；挑得到且 R3 成立才放，放了 `extrasPlaced += 1`、`extraDays.add(day)`。
- 挑不到（時間上限、保存期限、避開開關、14 天不重複全擋）或 R3 不成立 → **不補抽**、這一格照常排配菜。配額是「**最多**」不是「一定」，本週頁摘要照實講幾餐（R10）。
- 午餐、晚餐**不分先後**（Q3 的子項：要不要「優先晚餐」）。

### R6 與「本週想吃」「葷食保障」的關係
- 本週想吃的純葷菜：**照舊一定排**（不被配額擋），但**算進** `extrasPlaced` 與 `extraDays`（Q6）。所以「適中 3」＋勾了 1 道滷雞腳 → 配額加菜最多再 2 餐。
- 葷食保障加菜（主菜排不到葷）：照舊、**不算**配額（它是在補「每餐有葷」，不是多給）。但它佔了那一格，所以同一餐不會再有配額加菜（R4 自然成立）。
- 嘗試順序（那一格）：本週想吃純葷 → 葷食保障（`!mainMeaty`）→ 配額加菜（`autoOpen`）→ 一般配菜。前三個任一成功就 return。

### R7 挑哪一道純葷菜（不新增規則，全部沿用）
`pickForSlot(…, { meatOnlyExtra: true })` 走現有 `hardBlock` ＋ `scoreSoft`，所以自動吃到：時間上限（該餐的 cap，主食除外）、保存期限（離買菜日太久的魚肉不排）、同一天不排同一道、同餐不重複油炸／湯、避開開關、主菜 14 天不重複（`NO_REPEAT_PENALTY.main = 100`）、蛋白質輪替（同一天同蛋白質 −25、跟主菜撞蛋白質會被壓下去）、魚每週 ≥ 2 的加分、一週平衡（豐盛配額、油炸 1、加工醃漬 1、紅肉 5）、收藏＋12、當季、質地、採買效率、家裡有。
**不加**「現成的菜優先」之類的新分數（非目標）；滷雞腳 time 0 本來就過得了任何時間上限。

### R8 理由文字（`reasons[]`，只講事實）
- 配額加菜：沿用現有那句「這道是給吃葷的人的加菜（素食家人吃這一餐其他的菜）」，再加一句 `這週第 ${n} 餐給吃葷的人加菜，在一週 ${quota} 餐內`。
- 本週想吃加菜、葷食保障加菜：文字不變。

### R9 換一道／鎖定／指定／加一道／拿掉
- **換一道**：`swapItem` 對 `extraMeat` item 沿用 `meatOnlyExtra: true` → 換成另一道純葷菜（現況）。
- **鎖定**：鎖住的加菜重新產生時原樣保留（現況），而且**算進** `extrasPlaced`／`extraDays`（重新產生時先登記鎖住的菜那一段要把 `extraMeat` 的也算進去），配額才不會被鎖住的加菜撐爆。
- **指定／加一道／拿掉**：使用者手動的，不受配額管（現況），`pickRecipe` 已會標「誰吃不了」。
- 拿掉一道配額加菜之後那一格是空的，「換一道」會照 `MEAL_ROLES` 的角色補一道**配菜**（`swapItem` 的 `role` 取 `current?.role ?? MEAL_ROLES[…][pos]`，current 不存在 → side）。這是對的：拿掉就是不要它。

### R10 畫面
1. **家人頁「排菜規則」**新增小節「給吃葷的人多一道純葷的菜」，放在「一週豐盛程度」之後，四段 chip 自己一列（跟 `heartyLevelRow` 同一種版面，避免 STATUS 慣例 20 那次被擠成一欄一個字）。說明文字（`dataset.field = 'meatExtraHint'`）：
   > 家裡同時有吃葷、吃素的人時，一週有幾餐在配菜的位置多排一道只有吃葷的人吃的菜（例如滷雞腳、香煎鯖魚）。那一餐吃素的家人仍至少有兩道菜加主食。全家吃葷或全家吃素時不影響。改了之後下次「產生」或「重新產生」才會生效。
   後半句「仍至少有兩道菜加主食」是**誠實性文案**（跟「菜不夠時還是會重複」同一類），`familytest` 要守。
2. **本週頁**：新增一張卡（`dataset.card = 'meatExtra'`），**只在混合家庭而且現在的菜單裡有 ≥1 道 `extraMeat`** 時畫。文字從**現在的菜單**重算（換過、鎖過、拿掉的都算進去；不讀 diagnostics），純函式 `meatExtraSummary({ plan, recipes, members, rules })` 放 `js/planner.js`，回 `{ count, quota, names[], slots[] }`；句子：
   > 這週有 3 餐多排了一道只有吃葷的人吃的菜（滷雞腳、香煎鯖魚、蔥油淋雞），在一週 3 餐的設定內；那幾餐吃素的家人仍有至少兩道菜加主食。
   超過設定（鎖住、指定、本週想吃湊出來的）時尾句改「比你設定的一週 N 餐多了 M 餐（指定、鎖定或本週想吃的菜）」，不說「在設定內」。
3. 每道加菜的 pill「加菜」「僅葷食成員」、選單裡那句「這道是給吃葷的人的加菜…」：沿用。
4. 診斷卡 `noMeat`、`wantMissed` 的文字：沿用；`wantMissReason` 裡「每一餐要先讓他們吃得到至少 3 道，排不出多加一道葷菜的位置」仍然正確。

### R11 購物清單、每日估算、今日煮
- 全部從計畫推導，**不改程式**，但要**驗**：
  - 購物清單：純葷加菜是不分流的菜，`scaleFor` 走 `all / servings`，只按**吃得了的人數（＝吃葷的人）**縮放；混合 2 人家庭 → 倍數 1/servings，素食成員不買。
  - 每日估算：素食成員那一餐 `missing += 1`（畫面「吃不了 1 道」），數字不含那道；葷食成員含。
  - 今日煮時間線：純葷菜只有 base 步驟，合併照舊。

### R12 設定要一路傳到排菜器（STATUS 慣例 21）
`rules.meatExtraLevel` 要出現在**三個呼叫端**：`js/views/week.js` 的 `generate()`、`js/views/weekops.js` 的 `planArgs()`（換一道與外食改回自己煮走這裡）、本週頁算摘要的 `meatExtraSummary` 呼叫。`buildContext` 讀不到或值不合法 → 落回 `DEFAULT_RULES.meatExtraLevel = 'medium'`。

## 5. 與現有規則的交互（逐條）

| 現有規則 | 交互 | 結論 |
|---|---|---|
| 素食保障 `VEG_MIN_DISHES = 3` | 配額加菜放之前必過 R3 | **不衝突，且是唯一硬門檻**；值不改，`doctest` 那條照舊 |
| 每餐有葷（`requireMeaty`／葷食保障加菜） | 主菜位置不變；配額加菜只在 `mainMeaty` 時開 | 不衝突；葷食保障加菜不算配額 |
| 主菜 14 天不重複 | 加菜 role 是 main，`scoreSoft` 照扣 −100；`state.place` 記進 history | 不衝突；加菜會佔掉主菜池的「近期吃過」名額，但純葷池 41 道夠用 |
| 同一天不排同一道 | `hardBlock sameDay` 照擋 | 不衝突 |
| 同餐不重複油炸／湯 | `EXCLUSIVE_METHODS` 照擋 | 不衝突 |
| 一週平衡：豐盛配額、油炸 1、加工醃漬 1、紅肉 5 | `state.place` 與 `weekBalance` 都以 `role === 'main'` 計，加菜自動算進去；`heartySlots` 同餐第二道豐盛會覆蓋名字（只影響顯示，count 正確） | 不衝突；**一餐可能兩道豐盛主菜**（可分流主菜＋加菜）—— 分數層有同餐／同日的扣分壓著，可接受；`weekBalance` 要有斷言證明加菜有算 |
| 紅肉配額 5 在混合家庭壓不住（STATUS 記 7～8） | 純葷池雞 6、魚 13、牛 4：加菜多半會挑非豬的（同日同蛋白質 −25、紅肉超額 −40） | **預期改善**，要量：混合家庭紅肉／週在 medium 下應 ≤ 現況 |
| 魚每週 ≥ 2 | 純葷池魚 13 道 | 預期更容易達標 |
| 本週想吃 | R6 | 不衝突 |

## 10. 待 Yolin 拍板（純文字，附建議）

**Q1 門檻怎麼定（「素食有 2 道菜以上」的精確版本）**
- (a) **建議**：維持 `VEG_MIN_DISHES = 3`（含主食）＝「2 道菜＋飯」。放純葷加菜前算「放了之後素食成員還吃得到 ≥ 3 道」。常數、doctest、既有測試都不動。
- (b) 改成「2 道**不含**主食」：只差在主菜含主食（炒米粉）的午餐也放得下加菜（素食成員剩炒米粉＋1 配菜）。要改常數語意與一批測試，收益只有那 2 道菜。
- (c) 降到「2 道含主食」：素食成員午餐只剩 1 菜＋飯。**不建議**。

**Q2 一餐最多幾道純葷**
- (a) **建議**：1 道（就是那一格）。
- (b) 依保障算到多少放多少（晚餐可到 2：加菜＋純葷湯）。等於順便做 Q7，第一版不建議。

**Q3 一週幾餐、怎麼分散**
- 預設 **適中 3 餐**，家人頁可調 不排 0／少 2／適中 3／多 5；**每天最多 1 餐**；午晚餐不分先後。
- 子項：要不要「優先放晚餐」（晚餐有湯，素食成員少一道配菜的感覺比較輕）？**建議不加**，先用不分先後看實際感受，要加只是抽籤時加權。

**Q4 位置**
- (a) **建議**：沿用加菜位置（第二道配菜格），主菜位置永遠是素食成員吃得到的。
- (b) 純葷菜可以佔主菜位置：素食成員那一餐就沒有主菜（只剩配菜、湯、飯），要另做「素食成員的主菜保障」才安全。**不建議**。

**Q5 只在「有葷有素」的家庭觸發**
- **建議：是。** 全葷家庭純葷菜本來就直接當主菜（量到 7.8 道／週）；全素家庭永遠不排 `meatOnly`。

**Q6 「本週想吃」的純葷菜要不要算進配額**
- **建議：算進去但不被擋**（勾了一定排；配額加菜就少一餐）。不算的話「適中 3」實際可能變 4～5 餐。

**Q7 純葷湯（蛤蜊味噌湯、薑絲吳郭魚湯等 8 道）要不要也開放進晚餐湯格**
- **建議：第二階段。** 湯格被純葷佔掉時素食成員那餐沒有湯，而且會跟 Q2 的「一餐 1 道」互相牽動。先做主菜版本，看使用感受再說。

**Q8 畫面**
- **建議做**：家人頁四段設定（R10-1）＋本週頁摘要卡（R10-2）。不做設定的話只能寫死 3 餐，跟「一週豐盛程度」可調的慣例不一致。

**Q9 要不要開 3 個 Fable 代理投票**
- 這份規格的爭點集中在 Q1／Q3（門檻與配額數字），屬於使用感受，Yolin 直接拍板比投票準。**建議不投**；若 Yolin 想聽第二意見，可只針對「抽籤 vs 分數」與「配額預設 3」兩點投。

## 11. 驗收條件（Yolin 實測時看什麼）
1. 家人頁：排菜規則多一段「給吃葷的人多一道純葷的菜」，預設「適中（一週 3 餐）」。
2. 家裡設「爸 葷、媽 蛋奶素」，產生菜單：一週有 1～3 餐的第二道配菜位置是純葷菜，標「加菜」「僅葷食成員」；那幾餐媽仍有主菜（素版）＋1 配菜＋飯（晚餐再加湯）。
3. 本週頁多一張卡講「這週有 N 餐多排了一道只有吃葷的人吃的菜（菜名）」。
4. 設「不排」重新產生：加菜全部消失、卡片消失。
5. 自己加的「滷雞腳」（不勾本週想吃）在幾次重新產生裡會輪到（純葷池 41＋1 道、每週 ≤3 餐，不一定每週出現，但幾週內會）。
6. 全家吃葷：菜單跟改版前同種子**一模一樣**；全家吃素：一道純葷都沒有。
7. 買菜頁：加菜的肉只買吃葷的人的份。
