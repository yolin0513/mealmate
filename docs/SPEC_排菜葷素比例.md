# SPEC：排菜葷素比例 —— 讓「不可分流的純葷菜」在有素食成員的家庭也排得進去

- 日期：2026-09-16（草案）→ 2026-09-16 **定案**（Yolin 拍板，見 §10）
- 規劃：Fable 5.1（統籌 Session）。實作：MealMate 的 Opus 5 Session。
- 狀態：**定案，可實作。** 實作完成後逐條對照 §4 的 R1～R11 與 §8 的表回報。
- 對應需求（Yolin 原話）：「午餐、晚餐在『素食有 2 道菜以上』的情況下，可以有幾道是葷食；不然像『滷雞腳』這類無法分流（不能一鍋兩吃、只有葷版）的葷菜永遠排不進去。」

---

## 0. 一句話

家裡**同時有吃葷、吃素的人**時，**每一個午餐、晚餐**都在「第二道配菜」的位置改排一道**只有吃葷的人吃的純葷菜**（沿用現有「加菜／僅葷食成員」機制），前提是那一餐**素食成員仍吃得到 ≥ 3 道（＝2 道菜＋飯）**。沒有一週配額、沒有新設定、沒有新卡片：不想要哪一餐那道，用現有的「拿掉這道」拿掉。素食保障不降、全葷與全素家庭行為不變。

## 1. 現況（讀 `js/planner.js`、`docs/PLAN.md`、`docs/STATUS.md` 後的事實）

### 1.1 餐次組成與素食保障

| 常數 | 值 | 位置 |
|---|---|---|
| `MEAL_ROLES.lunch` | `['main','side','side','staple']`（4 格） | `js/planner.js` |
| `MEAL_ROLES.dinner` | `['main','side','side','soup','staple']`（5 格） | 同上 |
| `VEG_MIN_DISHES` | `3`：有素食成員時，每個午晚餐**每位素食成員都吃得到**的道數下限（**含主食**；主菜本身含主食如炒米粉時，被略過的主食格**不算**） | 同上，`doctest` 釘住 = 3 |

### 1.2 純葷菜（`vegMode === 'meatOnly'`）為什麼排不進去

1. `hardBlock()`：有素食成員時，一般位置的每道菜都要通過每位素食成員的 `versionFor() !== null`，純葷菜一律被擋（代碼 `diet:<名字>`）。
2. `generateWeek()`：家裡有吃葷的人時主菜硬性要求「葷」（`requireMeaty`），但可分流的主菜也算葷 —— 池子有 37 道可分流主菜，所以主菜幾乎每餐都是可分流的。
3. 唯一讓純葷菜進來的「加菜」位置（最後一道配菜格、`extraMeat: true`、畫面標「僅葷食成員」）**只在兩種情況開**：主菜排不到葷（`!mainMeaty`，真實池子幾乎不會發生），或使用者勾了純葷菜的「本週想吃」（v0.19.0）。
4. 加菜放之前會算 `vegDishesAfter() >= VEG_MIN_DISHES`，這條是對的、要保留。
5. 加菜那條路徑 `items.push()` 之後直接 `return`，**沒有**寫 `diagnostics.forcedRepeats`／`diagnostics.relaxed`（一般位置有寫）。以前加菜極少出現所以沒差，改成每餐都放之後就會漏報，要修（R7）。

### 1.3 量出來的現況（真實池子、6 個種子、`shoppingDays [3,6]`）

| 家庭 | 純葷主菜／週 | 可分流主菜／週 | 魚貝主菜／週 | 紅肉主菜／週 | 加菜／週 | 素食成員每餐最少吃到 |
|---|---|---|---|---|---|---|
| 全葷 3 人 | 7.8 | 6.2 | 7.7 | 4.8 | 0 | — |
| 爸葷＋媽蛋奶素 | **0** | 14.0 | 5.5 | 5.0 | 0 | 3 道 |
| 爸葷＋姊全素 | **0** | 14.0 | 8.0 | **8.0**（配額 5） | 0 | 3 道 |

池子結構：純葷主菜 41 道（魚 13、雞 6、豬 6、牛 4、蛋＋豬 3…；時間 ≤ 35 分的 31 道、≤ 40 分的 34 道、油炸 2 道）；可分流主菜 37 道（豬 15、雞 8、蝦貝 5、牛 4、魚 1…）。
**混合家庭 14 個午晚餐的主菜 100% 落在 37 道可分流主菜裡**：紅肉壓不到配額、雞與魚的純葷菜整批看不到、使用者自己加的滷雞腳除非勾「本週想吃」否則永遠不出現。這正是 Yolin 講的問題。

## 2. 目標與非目標

**目標**
1. 混合家庭（≥1 位 `omni` 且 ≥1 位非 `omni`）的**每個**午晚餐，在素食保障成立下，都排進 1 道純葷菜給吃葷的人。
2. 素食成員的保障**一道都不少於現在**（每餐仍 ≥ `VEG_MIN_DISHES`）。
3. 全葷家庭、全素家庭、沒有家人、早餐：**行為完全不變**（全葷家庭同種子菜單一模一樣）。
4. 一切照本 App 的慣例：純函式、固定種子固定結果、理由只講事實、勉強排的照樣進診斷、禁用詞零出現。

**非目標（這一版不做；Yolin 2026-09-16 拍板）**
- 一週配額／頻率設定（不做旋鈕；不想要就手動拿掉）。
- 本週頁摘要卡（保持介面簡潔）。
- 純葷菜佔**主菜位置**。
- 純葷湯（8 道）進晚餐的湯格（第二階段）。
- 全葷家庭「一餐兩道肉」。
- 依素食成員的蛋白質來源另做保障。
- 改 `MEAL_ROLES`、改 `VEG_MIN_DISHES` 的值。
- 「現成的菜優先」之類的新分數。

## 3. 名詞定義（規格與程式碼都用這幾個詞）

| 詞 | 定義 |
|---|---|
| **混合家庭** `mixedHome` | `ctx.vegetarians.length > 0 && ctx.hasOmni`。`hasOmni` 在**沒有家人**時也是 true，但那時 `vegetarians` 是空的，所以不算混合家庭。建議放進 `buildContext` 回傳值。 |

| **本週想吃加菜** | 現有行為：勾了純葷菜的「本週想吃」走加菜位置。不動。 |
| **每餐加菜** | 本規格新增：混合家庭每個午晚餐主動放的純葷加菜。 |

## 4. 規則（定案）

### R1 觸發條件
- 只在**混合家庭**開。全葷家庭純葷菜本來就直接當主菜；全素家庭永遠不放 `meatOnly`（現有紅線）。
- 只在午餐、晚餐；早餐不套用（沿用「早餐不要求葷」的決定）。
- 那一格沒有被鎖住的菜佔著（鎖住的優先，沿用現況）。

### R2 位置
- 沿用加菜位置：**該餐最後一道配菜的位置**（午餐 pos 2、晚餐 pos 2）。主菜位置**維持**「素食成員吃得到」（可分流或素），素食成員永遠有自己的主菜。
- 每餐加菜是「**用一道配菜換一道純葷主菜**」，那一餐的道數不變：午餐仍 4 道、晚餐仍 5 道。

### R3 素食保障（不變，是唯一的硬門檻）
- 放每餐加菜之前**先算** `vegDishesAfter(extra, pos) >= VEG_MIN_DISHES`（＝3，含主食）。算不到就**不放**，這一格照常排配菜。
- 換算成 Yolin 的說法：素食成員那一餐至少**「2 道菜＋飯」**（午餐：主菜素版＋1 配菜＋飯；晚餐：主菜素版＋1 配菜＋湯＋飯）。
- 主菜含主食（什錦炒米粉、螞蟻上樹）的午餐：素食成員只剩「炒米粉＋1 配菜」＝2 < 3 → **不放**，那餐兩道都是配菜；晚餐多一道湯 → 放得下。現有算法自然得出，照舊。

### R4 每餐上限
- 一餐**最多 1 道**純葷加菜（含本週想吃加菜、葷食保障加菜）。位置只有一格，程式上自然成立；規格明寫是為了日後開放純葷湯時有依據。

### R5 每餐都放（取代草案的配額抽籤）
- 沒有配額、沒有設定、沒有亂數：`mixedHome` 成立的每個午晚餐，到最後一道配菜的位置時就開加菜格。
- 那一格的嘗試順序：
  1. **本週想吃的純葷菜**（現況）：`pickForSlot(…, { meatOnlyExtra: true, strict: true, exclude: onlyThese(wantMeatOnly) })`。
  2. **一般純葷加菜**：`pickForSlot(…, { meatOnlyExtra: true })`。開的條件是 `!mainMeaty || mixedHome`（前者是現有葷食保障，後者是本規格）。
  3. 任一個挑得到**且 R3 成立**就放，`return`；都不行 → 這一格照常排配菜（不放寬任何限制去硬塞）。
- 不放的兩種原因記進 `diagnostics.meatExtraSkipped: [{ date, meal, why: 'vegGuarantee' | 'noCandidate' }]`，**只給測試與除錯用，不上畫面**（Yolin：介面保持簡潔）。
- 使用者不想要某一餐那道：用現有「⋯ → 拿掉這道」。拿掉後那一格是空的，再按「換一道」會照 `MEAL_ROLES` 補一道**配菜**（`swapItem` 的 `role` 取 `current?.role ?? MEAL_ROLES[…][pos]`，current 不存在 → `side`）。這是對的，不用改。
- 不做「一週幾餐」：Yolin 2026-09-16 決定。

### R6 與「本週想吃」「葷食保障」的關係
- 本週想吃的純葷菜：照舊一定排（順序 1 先挑，確保它拿到那一格而不是被分數更高的純葷菜佔走）。沒有配額了，不需要「算不算配額」這件事。
- 葷食保障加菜（`!mainMeaty`）：照舊。它跟每餐加菜走同一個 `pickForSlot` 呼叫，只是開的條件多一個 `mixedHome`。
- `wantMissReason` 裡「純葷的菜只能走加菜位置 → 素食保障排不出位置」那句仍然正確（炒米粉午餐就是那個情況）。

### R7 挑哪一道純葷菜（不新增規則，全部沿用；並補上漏掉的診斷）
- `pickForSlot(…, { meatOnlyExtra: true })` 走現有 `hardBlock` ＋ `scoreSoft`，自動吃到：時間上限（該餐的 cap）、保存期限（離買菜日太久的魚肉不排）、同一天不排同一道、同餐不重複油炸／湯、避開開關、主菜 14 天不重複（`NO_REPEAT_PENALTY.main = 100`）、蛋白質輪替（同一天同蛋白質 −25）、魚每週 ≥ 2 的加分、一週平衡（豐盛配額、油炸 1、加工醃漬 1、紅肉 5）、收藏＋12、當季、質地、採買效率、家裡有。
- **加菜也要寫診斷**（修 §1.2 第 5 點）：放加菜時，跟一般位置一樣算 `forcedRepeats`（14 天內重複且不是本週想吃）與 `relaxed`（`actualRelaxations` 非空）。建議把一般位置那幾行抽成 `recordPick(diagnostics, picked, …)` 兩邊共用，不要複製貼上。本週頁現有「這週有幾個地方是勉強排的」卡會自然把加菜的重複算進去 —— 這不是新卡片，是既有卡片不漏報。
- **池子夠不夠是要量的事**（慣例 22）：每週 14 道加菜、主菜 14 天不重複 → 兩週要 28 道不同的純葷主菜；池子 41 道，扣掉平日午餐時間上限 35 分擋掉的 10 道、離買菜日太久擋掉的魚（3 天）。**一週只買一次菜的家庭**魚有 4 天排不進來，重複很可能出現。這是池子結構，不是 bug：照實進 `forcedRepeats`，STATUS 記下量到的數字（§9）。若量到重複太多，補純葷食譜是另一張工單，不在本規格內。

### R8 理由文字（`reasons[]`，只講事實）
- 沿用現有兩句：主菜是葷的 →「這道是給吃葷的人的加菜（素食家人吃這一餐其他的菜）」；主菜是素的 →「這一餐的主菜是素的，這道是給吃葷的人的加菜」。
- 本週想吃加菜多一句「你勾了「本週想吃」」（現況）。
- 不加任何配額句。

### R9 換一道／鎖定／指定／加一道／拿掉／外食改回自己煮
- **換一道**：`swapItem` 對 `extraMeat` item 沿用 `meatOnlyExtra: true` → 換成另一道純葷菜（現況）。
- **鎖定**：鎖住的加菜重新產生時原樣保留（現況）。
- **指定／加一道／拿掉**：使用者手動的，不受本規格管（現況）。
- **外食改回自己煮**（`weekops.regenerateSlot`）：現在是逐個位置呼叫 `swapItem`，`current` 不存在 → 角色照 `MEAL_ROLES` → 那一格永遠補**配菜**，不會有加菜。改成每餐都放之後這會變成「同一條規則在兩個入口行為不同」（慣例 21 的形狀）。**要修**：把 `generateWeek` 裡「填一餐」的那段抽成 `fillMeal(ctx, state, slotInfo, { lockedItems, rng, diagnostics })` 並匯出，`generateWeek` 與新的 `planner.refillSlot({ plan, slotIndex, …planArgs, history })` 都用它；`regenerateSlot` 改呼叫 `refillSlot`。`refillSlot` 建 state 的方式比照 `swapItem`（其他格全部 `place`）。

### R10 畫面
- **不新增任何畫面**：沒有家人頁設定、沒有本週頁摘要卡（Yolin 拍板）。
- 沿用：每道加菜的 pill「加菜」「僅葷食成員」、選單那句「這道是給吃葷的人的加菜，素食成員吃不了；同一餐其他幾道他們吃得到。」、診斷卡 `noMeat`／`wantMissed`／`forcedRepeats`／`relaxed` 的既有文字。
- 家人頁「排菜規則」現有說明**不用改**；若 Opus 覺得使用者會疑惑「為什麼每餐都有一道只有吃葷的人吃的菜」，可在家人頁飲食型態那一段加**一句**事實描述（例如「家裡同時有吃葷、吃素的人時，午晚餐會多排一道只有吃葷的人吃的菜，吃素的家人仍至少有兩道菜加主食；不想要可以在本週頁拿掉」），走 `copytest`；**這是選配，不加也可以**。

### R11 購物清單、每日估算、今日煮
- 全部從計畫推導，**不改程式**，但要**驗**（現在每餐都有加菜，這三處的母體從「幾乎空」變成「每餐都有」）：
  - 購物清單：純葷加菜是不分流的菜，`scaleFor` 走 `all / servings`，只按**吃得了的人數（＝吃葷的人）**縮放；混合 2 人家庭 → 倍數 1/servings，素食成員不買。
  - 每日估算：素食成員那一天 `missing` ＝ 有加菜的餐數（畫面「吃不了 N 道」），數字不含那幾道；葷食成員含。
  - 今日煮時間線：純葷菜只有 base 步驟，合併照舊；那一餐「同時要顧幾個鍋」會多一個，這是事實描述。

## 5. 與現有規則的交互（逐條）

| 現有規則 | 交互 | 結論 |
|---|---|---|
| 素食保障 `VEG_MIN_DISHES = 3` | 每餐加菜放之前必過 R3 | **不衝突，且是唯一硬門檻**；值不改，`doctest` 那條照舊 |
| 每餐有葷（`requireMeaty`／葷食保障加菜） | 主菜位置不變；加菜格的開啟條件從 `!mainMeaty` 變成 `!mainMeaty \|\| mixedHome` | 不衝突 |
| 主菜 14 天不重複 | 加菜 role 是 main，`scoreSoft` 照扣 −100；每週 14 道加菜對 41 道純葷池 | **會咬**：見 R7 第三點，重複照實進 `forcedRepeats`，STATUS 記數字 |
| 同一天不排同一道 | `hardBlock sameDay` 照擋 | 不衝突 |
| 同餐不重複油炸／湯 | `EXCLUSIVE_METHODS` 照擋 | 不衝突 |
| 一週平衡：豐盛配額、油炸 1、加工醃漬 1、紅肉 5 | `state.place` 與 `weekBalance` 都以 `role === 'main'` 計，加菜自動算進去；一週主菜從 14 道變 28 道，配額數字不變 → 豐盛的比例自然下降，超額扣分照扣。`heartySlots` 同餐第二道豐盛會覆蓋名字（只影響顯示） | 不衝突；`weekBalance` 要有斷言證明加菜有算；STATUS 記混合家庭實作前後的豐盛／紅肉數字 |
| 紅肉配額 5 在混合家庭壓不住（STATUS 記 7～8） | 純葷池雞 6、魚 13、牛 4：加菜多半會挑非豬的（同日同蛋白質 −25、紅肉超額 −40）；但主菜總數變 28 | 紅肉**道數**可能持平或上升、**比例**下降；量出來記 STATUS，不用達標 |
| 魚每週 ≥ 2 | 純葷池魚 13 道 | 預期更容易達標 |
| 本週想吃 | R6 | 不衝突 |
| 鎖定／外食／不煮 | 外食格不排；鎖住的加菜保留；外食改回自己煮走 `refillSlot`（R9） | 不衝突 |
| 保存期限 | 加菜照 `shelfBlocker`；離買菜日遠時魚被擋 → 挑別的純葷菜或（都不行）不放 | 不衝突 |
| 「避開油炸／加工／精緻糖」 | `hardBlock` 照擋 | 不衝突 |
| 早餐 | 不套用 | 不變 |
| 全素家庭 | `mixedHome` false | **零 meatOnly，紅線不變** |
| 全葷家庭 | `mixedHome` false，且本規格不動主亂數串 | **同種子菜單一模一樣** |

## 11. 驗收條件（Yolin 實測時看什麼）
1. 家裡設「爸 葷、媽 蛋奶素」，產生菜單：**每個**午晚餐的第二道配菜位置是純葷菜，標「加菜」「僅葷食成員」；媽那幾餐仍有主菜（素版）＋1 配菜＋飯（晚餐再加湯）。排到炒米粉的午餐沒有加菜（媽只剩 2 道）。
2. 某餐「⋯ → 拿掉這道」把加菜拿掉 → 那格空；「換一道」補回一道配菜。
3. 自己加的「滷雞腳」（不勾本週想吃）在幾次重新產生裡會輪到（純葷池 41＋1 道、每週 14 道加菜、主菜 14 天不重複）。

7. 本週頁若出現「N 道在不重複天數內重複了」，加菜的重複有算進去（純葷菜不夠時會這樣，是誠實回報，不是錯）。
