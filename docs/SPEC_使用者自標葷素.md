# SPEC_使用者自標葷素 — 自己的食譜裡，加工品的葷素由使用者說了算；本週頁掛「我的」小標

> 狀態：**定案，待執行**

> 規劃：Fable 5.1 統籌 Session，2026-09-21。決策來自 Yolin 2026-09-19 的原話（§8）。事實依據：Opus 勘查員 2026-09-19 的實查＋統籌者 2026-09-21 對 `76bdaff` 的唯讀實查（行號以你現在讀到的為準）。

## 一句話

使用者自己的食譜裡，**加工品類**食材在資料庫的葷素標籤不再擋使用者的選擇（兩個方向都是）；本週頁替使用者自己的食譜掛既有的「我的」小標，讓他在菜單上看得出「這道的葷素是我自己標的」。

## 1. 現況（勘查事實）

- `validateRecipe`（`js/recipeschema.js`）逐樣食材用 `tagsOfFood` 取標籤；食材帶 `meat`／`seafood` 而這道菜標成「素」→ 擋下（「○○是葷的，但這道菜標成『素』」）；可分流而該食材不在葷那一欄 → 擋下。反方向：標成「葷」但沒有任何食材帶 `meat`／`seafood`、也沒有查不到的食材 → 擋下（「標成『葷』，但食材裡沒有肉或海鮮…」）；可分流而整道沒有肉或海鮮 → 擋下。
- **Yolin 舉的蛋餅皮兩邊都踩到**：v0.36.0 照食藥署那一筆的內容物描述把冷凍蛋餅皮標成葷（含豬油）→ 他買到素的蛋餅皮時，這道菜標不成素；反過來，沒有標記的加工品他想標成葷也不行。
- 成分不明（資料庫沒有標記）的加工品，現在就判成素、照排給所有素食家人、畫面沒有任何記號。**這是現狀，Yolin 知情並接受（§8 第二句）。**
- 食譜的 `tags`／`vegTags` 帶 `meat`／`seafood` → `members.versionFor` 不排給素食家人。所以光是「不擋存檔」不夠：被使用者推翻的那個標籤如果照樣寫進 `tags`，這道菜還是排不到素食家人。
- 另一條獨立的路（v0.18.0）：食材在資料庫**完全查不到** → 要使用者自己選一次「素葷」（`vegModeConfirmed`，表單的 `vegConfirm` 提示），而且標成素之後只排給蛋、奶、五辛三樣都吃的素食家人（`versionFor` 的 `unresolved` 分支）。
- 表單預設值是「素」（`vegMode: 'nativeVeg'`、`vegModeConfirmed: false`）；使用者點過「素葷」任何一顆才會是 `vegModeConfirmed: true`。
- 「我的」小標：食譜清單（`js/views/recipes.js`）與食譜頁已經有（`r.source === 'user'`）。本週頁一道菜那一列（`js/views/week.js` 畫一列的那一支）現在會放「加菜／僅葷食成員／自己加的／🔒」，註解記著小標太多會把「⋯」擠到下一行（使用者回報過）。
- 食材類別的確切字串（`data/foods.json`）：`加工調理食品及其他類`（313 筆）、`糕餅點心類`（116）、`調味料及香辛料類`（149）。

## 2. 目標與非目標

**目標**：G1 使用者自己的食譜，加工品的葷素以他選的為準，兩個方向都存得進去、也照他選的排；G2 他沒有真的選過就不算他選的（表單預設值不是判斷）；G3 菜單上看得出哪幾道是他自己的食譜；G4 原型食材、內建食譜、「查不到的食材」三件事的行為一個都不變。

**非目標**：
- **不動「資料庫查不到的食材」那條保守規則**（`unresolved`：只排給蛋、奶、五辛三樣都吃的素食家人）。【Yolin 2026-09-19 已決定維持現狀，見 §8。這不是「還沒決定」，也不是漏掉——不要順手一起放寬。】
- 不動蛋、奶、五辛、過敏原的標籤：加工品在資料庫標了含蛋、含奶、含五辛、含花生、含麩質的，照舊生效（Yolin 講的是葷素，不是這些）。
- 不動原型食材：肉類、魚貝類的食材照舊擋。
- 不動內建食譜、不動 `data/foodtags.json`（v0.36.0 逐筆確認過的標籤保留，內建食譜照舊用）。
- 不新增畫面元素、不新增詞、不新增提醒卡；不在排菜理由裡加句子。

## 3. 名詞

| 名詞 | 意思 |
|---|---|
| 加工品類 | 食材的 `cat` 是 `加工調理食品及其他類`、`糕餅點心類`、`調味料及香辛料類` 三者之一。做成一個具名常數，不要散落字串 |
| 推翻 | 使用者自己的食譜（`source === 'user'`）、使用者真的選過素葷（`vegModeConfirmed === true`）、而且那樣食材屬於加工品類 —— 三個條件同時成立時，那樣食材的 `meat`／`seafood` 標籤與使用者的選擇衝突，以使用者為準 |

## 4. 規則

- **R1 標成素（或放在可分流的共用／素那一欄），而加工品類食材帶 `meat`／`seafood`**：
  - 使用者選過素葷 → **不擋**；而且那樣食材的 `meat`、`seafood` 兩個標籤**不寫進**這道菜的 `tags`／`vegTags`／`meatTags`，也不拿去算 `proteinGroupOf` 與 `isProcessedFood`（用去掉這兩個標籤之後的集合）。它的其他標籤（蛋、奶、五辛、過敏原）照常寫入。
  - 使用者**沒選過**（還是表單預設的「素」）→ **照舊擋下**，但訊息改成講得出下一步的話：點名那樣食材、說資料庫那一筆是葷的、如果他買的是素的就在「素葷」自己選一次。表單上沿用既有的 `vegConfirm` 提示位置（不是新元素）；他點過之後就存得進去。文案你定，過 `copytest` 與 `CLAUDE.md` 第 5 條的禁用詞。
  - 這一條是統籌者加的安全邊界，理由：表單預設就是「素」，沒有這一條的話，使用者加了含豬油的蛋餅皮、沒碰素葷就存，會**從「被擋下」變成「靜默排給素食家人」**。Yolin 的原意是「使用者自行判斷」，預設值不是判斷。這跟 v0.18.0 對查不到的食材用的是同一個機制、同一個理由。
- **R2 標成葷，而沒有任何食材帶 `meat`／`seafood`**：食材裡至少有一樣加工品類 → 不擋（他買的那一款是葷的）。一樣加工品類都沒有（整道都是原型的蔬菜、豆腐）→ 照舊擋。需不需要 `vegModeConfirmed`：標成「葷」一定是使用者動手點的（預設是素），所以不另外要求。
- **R3 可分流而整道沒有肉或海鮮**：葷那一欄至少有一樣加工品類 → 不擋；否則照舊擋。
- **R4 原型食材不變**：肉類、魚貝類（以及其他非加工品類但帶 `meat`／`seafood` 的食材）標成素 → 照舊擋，訊息照舊。
- **R5 內建食譜不變**：`source !== 'user'` 的完全走原本的路。重建 `recipes.json` 前後一個位元組都不該變。
- **R6 查不到的食材不變**：`unresolved` 那條路的三處（要使用者選一次、標籤寫 `unresolved`、`versionFor` 保守地不排）原樣保留。一道菜同時有「被推翻的加工品」與「查不到的食材」→ 兩條各走各的，後者照舊保守。
- **R7 本週頁掛「我的」小標**：一道菜那一列，食譜是使用者自己的（`source === 'user'`）→ 掛 `pill('我的', 'accent')`，樣式與食譜清單上那個一致。**全部自訂食譜都掛，不只掛被推翻的**（Yolin 拍板，§8）。小標的順序與擠版：那一列已經有小標太多會把「⋯」擠到下一行的前科——請實測最擠的組合（自己的食譜＋自己加的＋🔒；自己的食譜＋僅葷食成員＋🔒）在 320 寬、特大字級不溢出、「⋯」不掉到下一行；放不下就調順序或讓小標那一格自己換行，做法你定並寫進回報。今日煮頁**不加**（勘查時如果發現它共用同一支畫列的函式、會自動帶出來，先回報，不要自己決定）。
- **R8 已經存著的食譜**：不做遷移。以前因為被擋而存不進去的，本來就不存在；已經存著的，標籤照存檔當時的不變，使用者下次編輯、存檔時才照新規則重算。

## 5. 與現有規則的交互

| 現有規則 | 會不會衝突 | 結論 |
|---|---|---|
| `versionFor`（誰吃得到）| 被推翻的標籤不寫進 `tags`，所以照使用者選的排 | 想要的。`js/members.js` 不用改；如果你發現非改不可，先回報 |
| 「避開加工肉與醃漬」開關（`processed`）| 被推翻成素的加工品不再因為 `meat` 被算成加工肉；名稱命中的（香腸、火腿…）照舊算 | 合理：他說那是素的 |
| 蛋白質輪替／達標（`proteinGroupOf`）| 被推翻成素的加工品不再回 `meat` 等 | 合理 |
| 過敏原、蛋奶五辛 | 不動 | 照資料庫 |
| 健康紅線、文案規則 | 新訊息一句 | 過 `copytest` |
| 備份匯入 | 不經過 `validateRecipe`（統籌者實查）| 不受影響 |
| 複製內建食譜成自己的（`draftFrom` 的 copy）| 複製時 `vegModeConfirmed` 會歸零 | 想要的：複製來的蛋餅要改成素，得自己點一次 |
