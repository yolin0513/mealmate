## 0. 一句話

一個**免帳號、純前端、離線可用、零外部請求**的 PWA，給「每天要煮三餐、家裡有長輩、可能有素食成員」的家庭掌廚者：設定家人（慢性病留意項目、葷素、人數）與買菜日，一鍵產生**一週菜單**（主菜兩週內不重複、素葷可「一鍋兩吃」分流），每道菜附**估計營養標示**（食藥署開放資料累加），並依買菜日自動彙整**購物清單**；可收藏、可手動加菜、可換菜、可鎖定。**它是規劃助手，不是營養師，也不是醫囑。**

## 1. 健康與安全界線（最先講，其他設計都受它約束）

### 1.1 定位

| 是 | 不是 |
|---|---|
| 家庭三餐**規劃與採買**工具 | 醫療器材、治療餐、營養處方 |
| 營養數字＝「**估計值，僅供參考**」 | 可拿去對照醫囑或藥量的數據 |
| 慢性病設定＝「**留意項目**」（顯示哪些欄位、怎麼排序） | 「糖尿病餐」「腎臟病餐」這種宣稱 |
| 衛教引用＝國健署公開手冊的**一般常識**，附來源 | 治療建議、目標值、劑量 |

這條界線與 StockDiary「不給投資建議」同一種形狀，作法也一樣：**文案禁用詞掃描進 `npm test`，有對照組**。

### 1.2 UI 怎麼呈現：既有用又不誤導

1. **首次啟動一頁說明**（非彈窗轟炸）：三句話——「營養數字是依食藥署資料庫估算，會跟實際有差」「慢性病設定只影響顯示與排序，不是治療建議」「長輩實際飲食請以醫師或營養師指示為準」。按「我知道了」進入；設定頁常駐同一段文字。
2. **每個營養數字前有「估」字**，例如「估 醣 42 g」；點開看「怎麼算的」：列出每個食材 × 克數 × 食藥署條目名稱，最後一行「資料來源：衛福部食藥署 食品營養成分資料庫 2026-08 版；未計烹調吸油與水分變化」。可追、可驗、不神秘。
3. **慢性病成員的卡片只顯示「留意欄位」**：糖尿病 → 醣、糖、膳食纖維；高血壓 → 鈉；腎臟病 → 使用者勾選的鈉／鉀／磷／蛋白質；高血脂 → 飽和脂肪、膽固醇。其他欄位在詳情頁。長輩看的是三個數字，不是十一個。
4. **「一般衛教參考」而非「你的目標」**：每日彙總旁可展開「國健署一般成人參考範圍（版本、連結）」，字級較小、灰色。**個人目標欄位預設空白**，說明文字：「若醫師或營養師有給你每日目標（例如醣類幾克），可填在這裡，App 只做加總對照，不會自己建議目標。」——與 StockDiary 試算器「所有假設由你輸入」相同。
5. **禁用詞**（UI、食譜資料、說明、測試對照組都適用）：治療、療效、控制血糖、降血糖、降血壓、改善腎功能、適合糖尿病患、糖尿病專用、腎臟病專用、減重、瘦身、排毒、保證、取代醫囑（肯定句）、建議攝取、應該吃。允許：低醣、低鈉、醣量標示、留意鈉、鉀較低、來源。
6. **腎臟病不自動限鉀**：衛教一致指出限鉀只在血鉀高或醫囑時。App 只讓使用者勾「醫師要我留意哪些」，勾了才標示、排序；不勾就不管。
7. **過敏原**：食材標籤推斷出「含花生／含海鮮／含蛋／含奶／含麩質」，UI 寫「依食材推斷，加工品成分請看包裝」，**不寫「無過敏原」**。

## 3. 架構

```
GitHub Pages（yolin0513.github.io/mealmate）
  ├─ index.html / css / js（原生 ES Modules；CSP script-src 'self'; connect-src 'self'）
  ├─ sw.js（SHELL cache-first 釘死本版；data/ stale-while-revalidate；VERSION 每版 bump）
  ├─ data/foods.json        食材：{id(食藥署整合編號), name, aliases[], cat, n[12 項/100g，順序由檔案的 nutrients 欄宣告], unitWeight, buyUnit, shelfDays, tags[]}
  ├─ data/recipes.json      由 data/recipes/*.json 合併（build 時 schema 驗證）
  ├─ data/edu.json          衛教引用句：{id, text, source{org,title,version,url,fetchedAt}} —— UI 每句衛教文字都指向一個 id
  └─ scripts/               build-foods.mjs、build-recipes.mjs、各測試、mutationtest.mjs

瀏覽器：IndexedDB（家人、設定、週計畫、歷史、購物清單、使用者食譜、收藏）；沒有網路呼叫
```

### 3.1 資料模型（IndexedDB，DB v1）

| store | keyPath | 內容 |
|---|---|---|
| `members` | `id` | 暱稱、ageGroup、diet（omni／lactoOvo／vegan／veganNoAllium）、watch[]（diabetes／sodium／potassium／phosphorus／protein／satFat）、texture、allergens[]。**沒有倍率欄位**（v2 才加） |
| `settings` | `key` | shoppingDays[]、noRepeatDays{main:14, side:7, soup:7, breakfast:0}、disclaimerAcceptedAt、dailyTargets{}（**預設空**）、seed、fontScale |
| `userRecipes` | `id` | 與內建同 schema，`source:'user'` |
| `favorites` | `recipeId` | addedAt、wantThisWeek（布林，最多 7 道為真） |
| `plans` | `weekKey`（ISO 週） | slots[21]：{day, meal, kind(cook／eatOut／skip), items[{recipeId, role(main／side／soup／staple), locked}], reasons[]} |
| `history` | `[date+recipeId]` | 用來算「N 天內不重複」；跨週；早餐也記，但 `noRepeatDays.breakfast` 為 0 所以不扣分 |
| `shopping` | `rangeKey`（採買區間起訖） | items[{foodId, grams, buyQty, buyUnit, section, checked}]、pantry[]（`have` 欄位 2026-09-17 隨「家裡有」一起移除；舊備份留著不理） |
| `recipeNotes` | `recipeId` | 使用者對某道菜的備註（「爸爸不吃香菜」）、自訂份量 |

匯出／匯入：全部 store 一個 JSON（沿用 StockDiary `backup.js` 的 round-trip 與逐列先驗證再 clear 的做法）。**沒有金鑰 store**（v1 無 AI）。

```json
    {"stage": "veg",   "text": "素食份加入泡軟的香菇絲略炒即可。", "type": "cook"},
    {"stage": "meat",  "text": "剩下的加入豬肉片與醬油炒至肉熟。", "type": "cook"}

```

- `vegMode`：`nativeVeg`（本身素；含蛋／奶／五辛由食材標籤推）、`splittable`（可一鍋兩吃）、`meatOnly`。
- `track`：`base`（共用）、`veg`（素那鍋）、`meat`（葷那鍋）。**營養標示分兩欄**：素版＝base＋veg，葷版＝base＋meat，各除以該版份數（由家人組成算出）。
- `texture`：`normal`／`soft`／`minced`（長輩質地標籤，§5B）。`season`：月份陣列，空陣列＝全年（§5F）。
- **混合家庭（有葷有素）**：每個午晚餐在素食保障成立下，第二道配菜的位置改放一道只有吃葷的人吃的純葷菜
  （`extraMeat`，畫面標「加菜」「僅葷食成員」）；素食成員那一餐仍至少吃得到 `VEG_MIN_DISHES` 道（含主食）。
  詳見 `docs/SPEC_排菜葷素比例.md`（2026-09-16 定案）。不想要的那一餐用「拿掉這道」移除。
- 「全素」（`veganNoAllium`，原名「全素不含五辛」）：食材標籤 `allium`（蔥、蒜、韭、洋蔥、薤）→ 有此標籤的 base 食材會讓這道菜對全素不含五辛成員不可用（或標「可省略蔥蒜」若食譜宣告 `alliumOptional`）。
- 有 `splittable` 才會在煮菜頁顯示「分流時間線」；`nativeVeg` 全家一起吃；`meatOnly` 在有素食成員時只能當「葷食成員的加菜」。

## 4. 四項需求 → 具體設計

### 4.1 慢性病設定 → 選菜與標示

| 留意項目 | 顯示欄位（卡片） | 對排序的影響（不是硬過濾） | 使用者可切「避開」 |
|---|---|---|---|
| 糖尿病 | 估 醣 g／份、糖 g、膳食纖維 g | 高醣主食型主菜（炒飯、炒麵、羹）降分；同餐主食優先排全穀雜糧（**只在家裡設定的米種範圍內**：設白米時是地瓜飯；不因此自動換米，2026-09-18）；含精緻糖的菜（糖醋、蜜汁）降分 | 「避開含精緻糖的菜」 |
| 高血壓 | 估 鈉 mg／份 | 鈉／份高於池子中位數的菜降分；醃漬、加工肉降分 | 「避開加工肉與醃漬」 |
| 腎臟病 | 使用者勾選的：鈉／鉀／磷／蛋白質 | 只對勾選的欄位做降分；全穀、堅果、濃湯（磷、鉀）降分僅在勾選時 | 每項各自 |
| 高血脂 | 飽和脂肪 g、膽固醇 mg | 油炸、內臟、肥肉降分 | 「避開油炸」 |
| 糖尿病前期 | 估 醣 g／份、糖 g、膳食纖維 g | 這幾項高於同類菜中位數的降分 | — |
| 心血管疾病 | 飽和脂肪 g、膽固醇 mg、鈉 mg | 這幾項高於同類菜中位數的降分 | 「避開油炸」「避開加工肉與醃漬」 |
| 心臟衰竭 | 鈉 mg | 鈉高於同類菜中位數的降分 | 「避開加工肉與醃漬」 |
| 脂肪肝 | 糖 g、飽和脂肪 g | 這兩項高於同類菜中位數的降分 | 「避開油炸」 |
| 骨質疏鬆 | 鈣 mg | 只顯示數字，不改排序方向 | — |
| 腸道不順 | 膳食纖維 g | 只顯示數字 | — |

2026-09-16 擴充慢性病清單時釘住的界線：**沒有數字的病不放進清單**。食藥署資料庫只有 12 個欄位 ——
痛風要的普林、貧血要的鐵都沒有，放進清單只會是個空標籤，使用者卻會以為 App 在替他看那一項。

- 家中同時有糖尿病與高血壓成員 → 兩組欄位都顯示，排序分數相加。
- **每日彙總**：本週頁每日底部「今日估算（每人一份）」顯示留意欄位的加總；旁邊灰字「一般衛教參考：國健署 DRIs 第八版（連結）」；若使用者填了自己的目標才出現對照條。
- 「醣類份數」：**v1 不做，已延後**。原構想是糖尿病成員可切換顯示「約 N 份（1 份 ≈ 15 g 醣）」，
  但換算規則要對到可引用的原文才能寫進 `edu.json`，M0 沒拿到，所以畫面上**一個份數都不顯示**（`redlinetest` 盯著）。
  拿到來源之前不要恢復：份數會被當成「可以吃幾份」的處方讀。
- 「避開」開關是**使用者主動打開**的硬條件；預設全關。這是唯一會把菜排除出池子的慢性病相關機制，而且是使用者選的。

### 4.2 蛋奶素／全素 → 一鍋兩吃

- 家人設定決定「素版份數」與「葷版份數」。有素食成員時，週計畫規則：**每餐至少一道 `nativeVeg` 或 `splittable` 主菜**；`meatOnly` 只能是額外加菜且標示「僅葷食成員」。
- 煮菜頁（今日）把當餐所有菜的步驟依 `stage` 合併成**一條時間線**：共用備料 → 共用烹煮 → 「⚑ 盛出素食份」 → 素食收尾 → 葷食收尾。每一步有大按鈕「完成」。
- 購物清單同時計入 veg 與 meat 兩軌的食材（按份數比例）。
- 蛋奶素 vs 全素：食材標籤 `egg`／`dairy`；`nativeVeg` 的菜若含蛋奶，對全素成員自動標「含蛋／奶」並不可排給全素成員。
- 「鍋邊素」不做成獨立模式（定義因人而異）；使用者可把成員設成蛋奶素並在備註寫。

### 4.3 每週不重複 ＋ 買菜日 → 購物清單

**產生週計畫（純函式，固定種子可重現）**

```
輸入：recipes（內建＋使用者）、members、settings、history（過去 28 天）、favorites、weekKey、seed、lockedSlots
輸出：plans[weekKey]（每格含 reasons[]）、shopping[rangeKey...]、diagnostics（哪些格子被迫重複、為什麼）
```

每個午／晚格子**依 `MEAL_ROLES` 的位置順序**決定：午餐 主菜 → 配菜 → 配菜 → 主食，晚餐 主菜 → 配菜 → 配菜 → 湯 → 主食
（早餐一道）。主菜最受限所以先選，主食排最後才知道主菜本身是不是已經含主食（炒米粉這類就不再加一道）。

**主食的米**（2026-09-18 Yolin 定案）：家人頁設白米／糙米／五穀米，預設白米。**主食格只排該米種的飯**（看食材的食藥署名稱判斷；2026-09-18 起白麵條等沒有米的主食也不排），
白米在白飯、地瓜飯、芋頭飯之間輪；麵類當主菜的不受影響（本身含主食，主食格略過）。設定的米只有一道飯時，飯類主食不套「同一天不排同一道」。不因家人的留意項目自動換米。早餐的粥不受這個設定影響（2026-09-18 起有 6 道有主食的早餐）。
陣列裡有重複的角色，所以每道菜記的是**位置 `pos`**，不是角色。候選分數 ＝
- 不重複：主菜 14 天內出現過 → 大扣分（不是排除；池子不夠時才會被選到，並記進 diagnostics）
- 蛋白質輪替：同一天兩餐主蛋白來源（豬／雞／魚／豆製品／蛋）不同；一週內魚類至少 2 次（衛教常識）。
  **「可關」尚未實作**：`DEFAULT_RULES.fishPerWeek` 是寫死的 2，家人頁沒有這個開關。
- 慢性病：§4.1 的降分
- 收藏：加分；「本週想吃」：大加分
- 季節：當季標籤加分
- **採買效率**：同一採買區間內，已被選中的菜用到的食材再被用到 → 加分（高麗菜買一顆用兩餐）
- **保存期限**：距上次買菜日 > 該食材 `shelfDays` 的菜 → 不可選（葉菜 3、海鮮 3、肉類 4、豆製品 3、根莖 7、瓜類 7、凍肉／乾貨不限）。
  天數的真相來源是 `data/units.json`，`unittest` 盯著（改那個檔一定要跑它）。
  海鮮原本寫 2 天、肉類原本也是 2 天，實測會讓一週買兩次的家庭在離買菜日最遠那兩天排不出任何葷菜，所以放寬到 3／4 天。
  **這是排菜用的假設，不是食品安全建議**，資料檔的 note 也這樣寫。
  查天數時一個食材的**所有**口語詞都會拿去對 overrides（只看第一個的話，表上寫 30 天的「薑」會落回蔬菜類的 3 天）。
- 烹調時間：平日晚餐上限 40 分鐘。**「可設」尚未實作**：`DEFAULT_RULES.timeCaps` 是寫死的
  （平日 早 20／午 35／晚 40，假日 早 40／午 60／晚 60），家人頁沒有這個設定。
- 同餐不出現兩道同烹法（兩道炸、兩道湯）
- 質地：家中有 `soft`／`minced` 需求的成員時，每餐至少一道符合質地的主菜或配菜加分

早餐格子：從早餐池（10 道）輪替填入，不進不重複計分，可換、可鎖定、可外食。

**買菜日與購物清單**

- 使用者勾週幾買菜（1–7 天）。採買區間 ＝ 買菜日當天到下一個買菜日前一天；區間必須無縫、無重疊地覆蓋整週。
- 每個區間一張清單：把區間內所有格子的食材依 `food` 加總克數 → 用 `buyUnit`／`unitWeight` 換成「約 1 顆／半斤／1 盒」（顯示「約」）→ 依賣場分區排：蔬菜、水果、肉、魚貝、豆製品蛋奶、乾貨雜糧、調味。
  （原本還列了 `wasteRate`（廢棄率），App 從來沒用到，M5 瘦身 `foods.json` 時刪掉了，`datatest` 盯著它不會回來。）
- `pantry:true` 的（油、鹽、醬油、米、糖）**不列入主清單**，另一段「常備品，用完再勾」。
- 每項可勾「買了」。（2026-09-17 移除「家裡有」：它不扣採買量、也沒有跨餐追蹤，只是一個小加分；冰箱裡的剩菜用「自己指定菜」處理更直接。）
- **已過的清單**（2026-09-18 Yolin 定案）：**整個過去的**（它涵蓋的每一天都過了）不顯示；上面還沒勾掉的「自己加的」
  搬到下一張還沒過的清單，已勾的不搬（今天以後沒有清單時，那張照樣顯示）。注意「過去了」看的是它給哪幾餐，不是買菜日本身 ——
  星期四那天，星期三那張的買菜日雖然過了，買的卻正是今晚要煮的菜。
- 「複製成文字」→ 用 Web Share 或剪貼簿貼到 LINE；「印出」→ 週菜單＋清單的列印樣式。
- 週中改菜 → 只重算受影響的區間清單，已勾「買了」的項目保留。

### 4.4 收藏與手動加入 vs 自動規劃

- **收藏**：愛心；規劃時加分；「收藏」頁可勾「本週想吃」（大加分，最多 7 道）。
- **手動指定格子**：點格子 → 選菜（搜尋、篩選：素／快／低醣／收藏）→ 放入並**鎖定**；「重新產生本週」只動未鎖定的格子。「換一道」（單格重抽）2026-09-18 依使用者要求移除 —— 要換就「我來指定」，清單先列同角色的菜、其他角色接在後面並標出角色。
- **外食／不煮**：格子可標記，購物清單自動扣掉。
- **手動新增食譜**：表單——菜名、角色、份數、食材（**每個食材一個框**：打字＝查詢、點一筆就對到並把名稱填回同一個框，可再改名稱；改成認得的名稱自動換對應、認不得就維持原對應並寫「營養照 X 算」（2026-09-18）；搜尋 `foods.json` 的名稱與別名；**2026-09-18 起有「X平均值」的家族只列平均值那一筆、顯示成簡名「X」**，同家族的大中小、品種、取樣月份不列出來，資料與編號不動；選了食材自動換成直覺單位——採買單位的顆／把／條、調味料的大匙／小匙、蛋與蔬果的單位重、肉魚加「斤」（600 克），可切回克，**存的永遠是克**，另記 `entry` 讓下次編輯照原本的單位顯示；**數量選填**）、步驟（選填）、可否分流（選填，預設不可）、質地、季節。**克數沒填 → 該菜營養標示顯示「未估算」，不顯示 0**；填了才算。可從既有菜「複製一份修改」。

## 6. 介面（明亮時尚、好操作）

- 四個底部分頁：**本週**（預設）、**買菜**、**食譜**、**家人**。設定與「關於／資料來源」在家人分頁底部。
- 色系：暖白底、番茄紅主色、青綠輔色、芥末黃提示；標籤用圓角 pill；字級基準 17px、長輩模式 19px（設定可切）。深色模式 v1 不做。
- 所有可點元件 ≥ 44px（沿用 StockDiary 的 `uikittest` 全頁掃描，不只掃一顆）。
- **本週頁**：手機直向一天一卡（早／午／晚三列，每列主菜名＋配菜＋湯、留意欄位小字）；桌機七欄。頂部：「重新產生」「印出」；每格：點「⋯」→ 上排「鎖定｜拿掉」、下排滿寬「我來指定…」；卡上是菜名（旁邊「看食譜」）、一行簡單資訊（時間、烹法、當季、誰吃得了），「為什麼選這道」預設收起，**帶估算數字的理由不印在這張卡**（2026-09-18）。今天之前的日子不列出來（2026-09-18 Yolin 定案；桌機欄數跟著天數走）。有素食成員且開了「素食成員每餐排一道蛋、豆製品或奶類的菜」（家人頁排菜規則，預設開）時，排不到的餐在本週頁講明。彈窗在換頁時一律關閉。
- **今日煮**：從本週頁點今天 → 時間線（§5A）。
- **買菜頁**：依採買區間分頁籤（「週三買」「週六買」），清單依分區折疊，勾選有觸覺回饋，底部「複製」「印出」。
- **食譜頁**：搜尋、篩選 chip（素／可分流／快／軟質／低醣／低鈉／當季／收藏／我的）、卡片顯示時間與留意欄位；詳情頁：食材（可切份數重算）、步驟、營養標示（素版／葷版切換、「怎麼算的」）、加入本週、收藏、複製修改。
- **家人頁**：成員卡片新增／編輯；留意項目用大 toggle；買菜日用七個圓形日期鈕。
- 首次啟動三步：加家人 → 選買菜日 → 產生本週。任何一步可跳過。

## 7. 測試慣例（沿用 StockDiary，列出這個 App 的關鍵斷言與對應突變）

**規則不變**：每條斷言都要能用突變證明會紅；`noneOf`／`everyOf` 旁要有母體非空斷言；檢查器要有對照組；註解不是斷言；突變字串不寫死版本號；跑 `mutationtest` 期間不並行編輯；**含 regex 的測試碼一律用 Write 工具寫檔，不經 shell heredoc**（StockDiary 踩過：`\s` 變 `\\s` 不報錯、測試綠但永遠不命中）。

| 斷言 | 突變（改壞後測試必須紅） |
|---|---|
| 所有 UI 文案、`edu.json`、內建食譜文字不含禁用詞（§1.2 第 5 點）；母體字串數 > 500 | 對照組：暫時塞一句「有助控制血糖」→ 紅 |
| 每道內建食譜每個食材的 `food` 都存在於 `foods.json`，`grams > 0`，`steps.length ≥ 3` | 把一道菜的 `food` 改成不存在的編號 → 紅 |
| `splittable` 的菜必有 `base`、`split`、`veg`、`meat` 四類 stage，且至少一個 `veg` 與一個 `meat` 食材 | 刪掉一道菜的 `meat` 食材 → 紅 |
| 固定食譜（白飯 200 g ＋ 雞蛋 50 g ＋ 醬油 10 g）的估算等於手算到小數一位（期望值由 fixture 算出，不寫死） | 讓累加用「每單位含量」而非「每 100 克」→ 紅 |
| 素版營養不含任何 `meat` 軌食材；葷版不含 `veg` 軌 | 讓素版把 meat 也加進去 → 紅 |
| 全素（不吃五辛）成員的週計畫不含任何有 `egg`／`dairy`／`meat`／`seafood`／`allium` 標籤的菜；母體：池中有這些標籤的菜 ≥ 30 道 | 拿掉 allium 檢查 → 紅 |
| 池子夠大時（主菜 ≥ 40），4 週計畫的主菜 14 天內不重複；池子不夠時 `diagnostics.forcedRepeats` 非空且 UI 顯示「本週有 N 道重複」 | 拿掉 history 扣分 → 紅；拿掉 diagnostics → 紅 |

| 早餐格子不受不重複扣分（同一早餐可週一、週三重複） | 讓早餐也吃 14 天扣分 → 紅 |
| 同種子同輸入 → 同輸出 | 用 `Math.random()` → 紅 |
| 購物清單：同一食材跨餐加總正確；`pantry` 不進主清單但在常備段；葉菜不被排到買菜日後第 4 天以上；區間無縫無重疊覆蓋 7 天 | 各自改壞 → 紅 |
| 「外食」格子的食材不進清單 | 改壞 → 紅 |
| 手動食譜沒填克數 → 顯示「未估算」；DOM 中該菜不出現「0 g」 | 讓缺值當 0 → 紅 |
| 每日目標欄位載入時全為空字串；DOM 不含「建議攝取」「應該吃」 | 塞預設值 → 紅 |
| 時間線：`prep` 步驟都在 `cook` 之前；`split` 在同道菜的 `veg`／`meat` 之前 | 改排序 → 紅 |
| 路由完整性：所有 view import ⊆ SW SHELL；`h()` 拒絕 `html:` prop；任何頁不自己 `mount(#view)`；`app.js` 不被 import | 沿用 StockDiary `shelltest` |

## 10. 風險與不做什麼

### 10.1 不做

1. 任何**宣稱療效**的飲食（「降血糖菜單」「排毒餐」「護腎餐」）。
2. **可取代醫囑的治療餐**：不算個人每日醣量／蛋白質目標、不算胰島素或藥物、不做透析飲食、不做管灌、不做嬰幼兒與孕婦特殊飲食。
3. **健康資料上雲**：無帳號、無同步、無分析、無崩潰回報；家人的慢性病設定只在這台裝置與使用者自己的匯出檔。
4. 爬取或轉貼第三方食譜網站內容、使用他人照片。
5. 減重／熱量赤字功能；熱量只當一般資訊列出。
6. 「無過敏原」保證。
7. 痛風留意項目、完整冰箱庫存、社群分享食譜、多語、菜色照片、深色模式（理由見附錄 A）。

### 10.2 風險與對策

| 風險 | 對策 |
|---|---|
| 長輩或家人把數字當醫囑 | §1 的 UI 措辭、「估」字、禁用詞測試、每個數字可展開來源 |
| 食譜量不足 → 重複感 | v1 170 道；diagnostics 誠實顯示；手動加菜同 schema 立刻進池 |
| 營養估計偏差（吸油、調味料、生熟） | 調味料一律列入食材；標「未計烹調變化」；食材選用與烹法對應的條目（炸物用熟樣品） |
| 食藥署名稱對不上口語 | 別名表 ＋ 每道菜食材解析測試；搜尋用精確詞比對俗名，不用子字串 |

## 附錄 A：已否決與延後的方案（保留理由）

### A.1 已否決（不做）

| 方案 | 否決理由 |
|---|---|
| **痛風留意項目** | 食藥署資料庫**沒有普林欄位**（104 個分析項裡沒有），只能靠人工替菜色貼「高普林」標籤，準度低；且痛風飲食的個別差異大，更接近醫囑而非一般衛教。使用者 2026-09-12 同意不做 |
| 用 USDA FoodData Central 當營養來源 | 英文、美式食材、需外部 API；食藥署資料已足夠且授權明確 |
| 每道菜預標營養數字 | 手動加菜、改份量就沒數字；不可追溯 |
| 只用「過濾葷素」處理素食 | 使用者要的是「先煮素再加葷」，那是食譜結構問題；過濾只會讓有素食成員的家庭池子剩一半 |
| 腎臟病一律限鉀 | 衛教明確：限鉀只在血鉀高或醫囑時；一律限會誤導 |
| 完整冰箱庫存管理 | 維護負擔高、多數人一週內放棄；冰箱裡有什麼要用掉，直接用本週頁的「自己指定菜」排進去 |
| 菜色照片 | 沒有合法來源、體積大；用分類插圖／色塊 |
| 深色模式（v1） | 家庭廚房場景多白天、明亮主題是需求；先不花這個成本 |
| 後端／帳號／雲端同步 | 沒有需求需要它；健康資料上雲是風險不是價值 |
| 爬食譜網站 | 版權與服務條款；步驟文字受著作權保護 |
