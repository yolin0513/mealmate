# SPEC_嫩莢豆芽與蛋白質門檻 裁決一 — R5 的內部衝突、R6 文案、T5 對照

> 狀態：已執行（2026-09-19、mealmate-v0.37.0）
> 裁決：Fable 5.1 統籌 Session，2026-09-19。另開新檔是因為你的工作區有未提交的變更。與原規格衝突時以本檔為準。

## 0. 先講

你停下來是對的。R5 的衝突是統籌者的錯：寫「不動 `aliases.json`」時沒查買菜清單是靠別名表的詞去找採買單位。白飯的蛋白質也是統籌者寫錯（7.0 是生米的量級，熟飯 3.1）；T5 改用乾麵條當非蔬菜類對照，照你的。

## 1. R5：採 A，但別名要過撞名檢查

允許在 `data/aliases.json` 補別名，原規格 §「不動」清單裡的 `data/aliases.json` 這一項作廢（只限這 4 筆食材，不順手補別的）。

**每一個要加的別名先過兩關，過不了就換詞：**
1. 現在 `resolve(別名)` 是 null（不搶走已經對得到的東西）。
2. 這個詞不是**另一種食材**名稱的一部分。統籌者實查：**「扁豆」不行**——資料庫有 `紅扁豆仁`（豆類，是 lentil），現在打「扁豆」搜得到它；把「扁豆」設成鵲豆莢的別名，使用者寫扁豆湯時會被靜默算成豆莢。鵲豆莢請改用不撞名的詞（例如「扁豆莢」「鵲豆」「肉豆」，你照別名表現有的慣例挑，挑了什麼寫進回報）。「長豆」「甜豌豆」「大豌豆莢」統籌者查過名稱不撞，但請照上面兩關自己再驗一次（「甜豌豆」若你判斷會跟豌豆仁混淆，改用「甜豆」「甜豆莢」）。
- 測試：`aliastest` 守新別名；**加一條對照組斷言：`resolve('扁豆')` 不是鵲豆莢**（突變：把「扁豆」加進鵲豆莢的別名 → 這條紅）。
- 單位用「斤／600 克」可以，依據你寫的成立。補一件事請實查後回報：新增食譜時這 5 筆的**預設填寫單位**實際顯示什麼。食譜裡豌豆莢通常是 100–200 克，預設填「斤」不好填；如果 `units.json` 的結構允許「採買用斤、填寫預設用克」就這樣設，不允許就維持斤（使用者可以切回克），不要為此改 `js/units.js`。
- 更正一個轉述：「長豆」「扁豆」不是 Yolin 點名的，是統籌者規格裡的括號註解。Yolin 的原話只有四季豆、豌豆莢、豆芽菜，嫩莢類是他同意的歸類。不影響裁決，但 STATUS 別寫成 Yolin 說的。

## 2. R6：理由句照你的；本週頁加的那一行拿掉

- **理由句**「○○這一餐吃得到份量夠的黃豆芽」：採用。點名食材、不碰「蛋白質」「營養」，比統籌者的例子好。要求：食材名稱是**實際讓這道菜達標的那樣食材**動態帶入，不寫死「黃豆芽」（使用者自己的菜可能靠別的蔬菜達標）。T9 照這個斷言。
- **本週頁那一行小字「黃豆芽這類豆芽菜份量夠的也算，這幾餐也都沒有。」：拿掉**，`js/views/week.js` 還原成不動。理由：那張卡的標題「這幾餐排不到蛋、豆製品或奶類的菜給○○」在 R3 之後仍然是實話（那幾餐確實沒有）；不誠實的風險只在**達標時的理由句**，已經用上一條解決。多一行去解釋一個邊角，Yolin 的偏好是不加；而且 R3 是通則，寫「豆芽菜」反而不準。

## 3. R8：數字照實，門檻可以
