## 工作慣例（常設規則，給每一個接手的工作階段）

1. **使用者已授權自行執行**查詢、新增檔案、搬移檔案、git 操作（建 repo、commit、push、部署），**不必逐項請示**。只有「刪除使用者資料」「花錢」「動到其他專案（JLPT_App、TripQuest、StockDiary）」才要問。
2. **重大決策開多代理投票**：架構、資料結構、部署方式、需付費或註冊的服務 → 開 **3 個 Fable 5.1（`claude-fable-5-1`）代理**、同一份 prompt、各自獨立、多數決；分歧採保守；決議寫進回報與本文件。規劃期**沒有開**（純前端單一架構、無付費服務），使用者 2026-09-12 確認；開發期照 `PLAN.md` 做不需要開，**要偏離 PLAN 的架構或資料結構時才開**。
3. **Fable 額度用盡就自動改用 Opus 5，不要停下來問。** 代理因 429／quota 失敗 → 自動改 `claude-opus-5` **整批重跑**（投票要在同一模型上才可比），回報中註明「因 Fable 額度用盡改用 Opus 5」。只有 Opus 5 也不可用時才暫停。
4. **測試不得有假斷言。每條斷言都要能用突變測試證明它真的會紅**：把對應邏輯改壞（例如讓素版營養把葷軌加進去、讓慢性病降分變成排除、讓缺克數當 0），測試必須失敗；修回去必須綠。檢查器（禁用詞掃描、食材解析、regex 跳脫掃描）要有**對照組**：餵已知該被抓到的輸入，斷言真的抓到。「應該是 0」的斷言旁邊要有「母體非空」的斷言。註解不是斷言。寫完一條 `noneOf`／`everyOf` 就問一次：**這個母體現在有幾個元素？** `everyOf([1], () => true)` 是 `ok(true)` 換衣服，不算斷言。
5. **含 regex 的測試碼一律用 Write 工具直接寫檔，不要經過 shell heredoc。** StockDiary 踩過：`\s` 變成 `\\s`，在 regex 裡是「反斜線接字母 s」，**不報錯、測試綠、但那條斷言從此不命中任何東西**，實際有兩條守最重要事情的斷言就這樣失效了一段時間。`shelltest` 要有「regex 字面值裡出現雙反斜線＋類別字元」的掃描，跳過註解與字串，並附兩條對照組（認得出壞的、不誤報好的）。
6. **繁體中文介面**；文案誠實——算不出來就寫「未估算」「尚未設定」，不顯示 0、不用預設值冒充使用者輸入、不用舊資料冒充新資料。
7. **健康界線（本 App 的第一條紅線）**：
   - **不得出現療效宣稱、治療處方、可取代醫囑的內容**——UI 文案、內建食譜文字、`edu.json`、說明頁、測試對照組全部適用。禁用詞清單在 `PLAN.md` §1.2 第 5 點，由 `copytest` 掃描，母體非空、有對照組。
   - **營養數字一律標「估」，且可展開來源**：食材 × 克數 × 食藥署條目名稱 ＋ 資料庫版本 ＋「未計烹調變化」。null 就是「未估算」，不是 0。
   - **慢性病只做一般衛教，不做治療建議**：留意項目只影響「顯示哪些欄位」與「排序分數」，**不硬過濾**（唯一的排除是使用者自己打開的「避開」開關）；**不算個人目標**，目標欄位預設空白由使用者填；**腎臟病不自動限鉀**，只對使用者勾選的鈉／鉀／磷／蛋白質作用；每一句衛教文字都指向 `edu.json` 的一個 id，該 id 有來源標題、版本、網址、擷取日。
8. **不做帳號、雲端、任何外部請求。** 家人的健康設定只在本機 IndexedDB 與使用者自己的匯出檔。程式碼裡出現非同源 `fetch(` → `shelltest` 紅。
9. 沿用 JLPT_App／TripQuest／StockDiary 技術路線：原生 JS ES Modules ＋ IndexedDB ＋ Service Worker，無框架、無打包；`h()` 全 textNode、URL 屬性白名單；CSP `script-src 'self'`；**任何一頁不准自己 `mount(#view)`，一律走 `shell.js` 的 `render()`**（router 的 `gen`／`paintGen` 守門照抄 StockDiary）；**`js/app.js` 是進入點，不准被任何模組 import**；`index.html` 每個網址帶不帶版本參數要跟模組圖一致。三條都有 `shelltest` 靜態稽核。
10. **資料授權標示**：食藥署資料（政府資料開放授權條款第1版，與 CC BY 4.0 相容）→「關於」頁與每個營養標示的「怎麼算的」底部標示「資料來源：衛生福利部食品藥物管理署 食品營養成分資料庫（YYYY-MM 版）」。國健署引用：只用文字、不用圖像（開放宣告排除影音圖像，M0 確認）。
11. 每版流程：bump `sw.js` VERSION → `npm test`（受影響的）→ commit/push → curl 確認線上 VERSION → `npm run sweep`（線上巡檢）→ 截圖放 `screenshots/features/`。
12. 打真網路的測試：**沒有**（App 無網路呼叫）。`build-foods.mjs` 是開發者本機工具，不進 `npm test`；它的解析邏輯用固定樣本（幾列白飯的原始列）做 `datatest`。
13. 不動 `D:\Claude\App\TripQuest`、`D:\Claude\App\JLPT_App`、`D:\Claude\App\StockDiary` 的任何檔案（可讀，用來抄慣例：`ui.js` 的 `h()`、`router.js` 守門、`backup.js` 逐列先驗證再 clear、`shelltest` 的靜態稽核、`layouttest`／`uikittest` 的全頁掃描）。
14. **斷言驗語意、不貼字面。** 文案一改就紅的斷言（`includes('還沒有持股')` 那種）要改成驗語意（筆數、連結指向、幾個關鍵詞之一），不要只把字串換新。
15. **測試範圍：平常只跑受影響的，全面檢測由使用者叫**（沿用 StockDiary 的使用者指示）。判斷受影響：`grep -l "views/<改到的檔>" scripts/*.mjs`；改到 view 要加上會走那條路由的端對端測試；`css/style.css` → `layouttest`、`uikittest`；`js/app.js`／`router.js`／`shell.js` → `shelltest`、`racetest`、`versionmixtest`；`js/db.js`／`store.js` → `backuptest`、`plannertest`、`shoppingtest`。**沒有放寬的那一條：新的斷言仍然必須經突變驗證會紅。** 寧可多跑一支，不要漏。

## 接手者最容易做錯的事

1. **把慢性病設定做成硬過濾。** 留意項目只決定「卡片顯示哪三個數字」與「排序分數」。一旦變成過濾，有糖尿病長輩的家庭池子會剩一半、重複感暴增，而且等於 App 在替醫師決定「這道不能吃」。唯一的排除是使用者自己打開的「避開」開關。`plannertest` 要有「池子只剩高醣主菜時仍排得出菜」的斷言，突變「降分改排除」必須紅。
2. **腎臟病自動限鉀（或限蛋白）。** 衛教一致：限鉀只在血鉀高或醫囑時。只對使用者勾選的鈉／鉀／磷／蛋白質計分，沒勾的欄位連分數都不參與。突變「鉀永遠計分」必須紅。
3. **營養數字沒標「估」、不能展開來源，或把 null 當 0。** 食藥署有些值是空的，手動食譜可能沒填克數——那一欄要寫「未估算」，不是 0；每個數字都要能點開看「食材 × 克數 × 條目 ＋ 版本」。「顯示 0」在這個 App 等於對長輩說「這道菜沒有鈉」。
4. **素葷合成時間線時把兩版營養加在一起。** 時間線合併的是**步驟**（依 stage／type 排序），營養永遠是素版＝base＋veg、葷版＝base＋meat，各除各的份數。把 veg 與 meat 兩軌都加進同一份會讓數字憑空多三成。`nutritiontest` 的突變「素版含 meat」必須紅，`timelinetest` 要斷言時間線頁仍是兩欄。
5. **用名稱字串（尤其子字串）去查食藥署營養。** 實測：「白米」0 筆、「豬」83 筆前幾筆是馬齒莧、「雞」撈到鷹嘴豆。食譜只存整合編號；口語詞經別名表精確比對；`aliastest` 有「搜豬不回馬齒莧」的對照組。

另外三件較小但會一路痛的：**早餐納入不重複計分**（10 道早餐兩週就耗光，早餐 `noRepeatDays` 是 0）；**池子不夠時靜默重複**（要進 `diagnostics` 並在本週頁明講「本週有 N 道重複，因為符合條件的菜只有 M 道」）；**用 heredoc 寫含 regex 的測試**（常設規則 5，寫測試一律 Write 工具）。
