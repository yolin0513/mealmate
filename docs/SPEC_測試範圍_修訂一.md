# SPEC_測試範圍 修訂一 — 不做挑選器；每版照舊全跑，只拆出突變並加上提醒

> 狀態：已執行（2026-09-19）
> 撰寫：Fable 統籌 Session，2026-09-19。這是對你「十三版回放沒過、停下來等裁決」那份回報的裁決。另開新檔是因為你的工作區有未提交的變更，統籌者不去動你可能正在改的檔。
> **本檔取代 `docs/SPEC_測試範圍.md` 的 R1–R5、§6 的「新增」、§7 全部、§8 的回放驗收。** 原規格的 R6–R9 與 §6 的文件修改仍然有效，但照本檔 §3 調整。兩份衝突時以本檔為準。

## 0. 先講裁決

**不是 A，也不是 B：不做挑選器。** 你沒有調規則湊數字、自己試算排除了放大器 P、還量了實際秒數——裁決靠的就是你量的那個數字：**26 支跑一輪 448 秒，約 7.5 分鐘。**

1. 這個 App 真正貴的是突變整套（30–40 分鐘），而那一層**早就放寬了**（每版只跑新增的幾條＋`checkmutations`）。Yolin 要的「不用每次小改動都全測」，在 MealMate 的大頭已經實現。
2. 剩下的 7.5 分鐘結構上省不掉。你查出的根因成立：13 版裡 10 版改到排菜器或成員模組，而幾乎每支瀏覽器測試都真的靠它們造資料。
3. **B 的兩個方向不採。** 那些測試不是「順便 import」，它們真的執行排菜器；v0.33.0「菜單變了 → 買菜頁在 320 寬特大字級溢出 3px」就是這樣被抓到的。把它們算成不受影響，是拿涵蓋換時間。
4. **A 也不採。** 「受影響 ≈ 全部」的 App 裡，挑選器只剩複雜度（三個腳本、一支測試、一批突變、跟 `doctest` 的耦合），換來 13 版裡 2 版的節省。而 A 列的那幾項價值，沒有一項需要挑選器——見 §2。

統籌者要承認：原規格的目標 G1「平常一版的測試時間明顯下降」在這個 App 達不到，而統籌者在沒有秒數的情況下就寫了它。**G1 作廢**，不是留著一個永遠達不到的目標。

## 1. 已經寫好的挑選器怎麼處理

`scripts/affected.mjs`、`scripts/run-affected.mjs`、以及 `scripts/bump-version.mjs` 匯出三條版本樣式的改動：**不要 commit，也先不要丟掉。** 這個裁決推翻的是 Yolin「點名要做」的字面，統籌者會請 Dispatch 讓他知道；他若堅持要挑選器，這些還用得上。

做法：把這三處改動存成一個 patch 檔放到你的 scratchpad（不是 repo 裡），然後把工作區還原乾淨（兩個新檔移走、`bump-version.mjs` 還原）。在你的 STATUS 交接節記一行：patch 存在哪、為什麼保留、等誰的答覆。Yolin 確認不要之後再刪。

## 2. 這一批實際要做的（全部不需要挑選器）

**2-1 `mutationtest` 拆出 `npm test`。** `package.json` 的 `test` 鏈拿掉最後一段 `mutationtest`；`npm test`＝26 支、不含突變；`npm run mutationtest` 是獨立指令，`--only` 照舊。（你回報過、勘查員也查過：`doctest` 驗「每支都在鏈裡」的母體裡沒有 `mutationtest`，沒有任何突變以 `package.json` 為目標，拆出去不會弄紅東西。拆完請實跑 `doctest` 確認。）

**2-2 每版要跑的，明文寫成本 App 的規定：**
- **每版**：`npm test`（26 支，約 7.5 分鐘）＋`npm run checkmutations`＋這一版新斷言的 `npm run mutationtest -- --only <關鍵字>`。
- **唯一的放寬**：只改 `docs/**`、`*.md` 的 commit → 跑 `doctest`＋`copytest` 就好（兩支純 Node、幾秒）。其他一律全跑。這一條靠人判斷沒有風險：判斷標準只有「有沒有改到文件以外的檔」，`git status` 一眼看得出來。
- 這不違反共用慣例 §5.7：那一條是解除義務、不是設上限，「本 App 規定每版要跑哪些的，照本 App」。本 App 的規定就是全跑，理由是它只要 7.5 分鐘、而受影響的範圍本來就幾乎是全部。
- 工作慣例第 15 條那張人工對照表：**整段刪掉**，換成上面這幾行與理由。那張表漏了五支測試，而全跑就沒有「漏」這回事。原規格要把它搬進測試當對照組，現在不必了。

**2-3 全面檢測的定義與兩行紀錄（原規格 R6，照舊）。** 全面檢測由 Yolin 指定才跑＝`npm test`＋`npm run mutationtest`（整套）＋`npm run assertaudit`＋`npm run checkmutations`。STATUS「測試現況」新增兩行固定格式的紀錄：
- 「上次全面檢測：日期、版本、結果、總耗時、最慢五支秒數」
- 「上次突變整套：日期、版本、條數、結果、耗時」

**基準照你查到的填：上次突變整套＝2026-09-13、v0.7.0（commit `9e80429`）、105 條全綠。** 原規格把它跟「349 條」寫在一起是統籌者的錯——105 條之後長到現在的 366 條，多出來的 261 條**從來沒有整套跑過**，這比「一週沒跑」嚴重得多，請照這個口徑寫進 STATUS。「上次全面檢測」的基準：沒有完整紀錄就照實寫查得到的部分，其餘寫「無紀錄」。耗時填你量到的：26 支約 448 秒；最慢的是 layouttest 101、plannertest 80、weekviewtest 53、recipeviewtest 37、racetest 與 versionmixtest 各 30。

**2-4 每版回報最後兩行提醒（原規格 R7，照舊，但不靠挑選器）。**
- 「距上次全面檢測：N 版／D 天」「距上次突變整套：N 版／D 天；其中 M 條從未整套跑過」。
- 做一支很小的 `scripts/sincefull.mjs`（`npm run sincefull`）：讀 STATUS 那兩行、算天數與版數、印出這兩句。**那兩行格式對不上就報錯並 exit 1，不准印 0 天。**「M 條從未整套跑過」＝現在的突變總條數減去上次整套跑的條數。
- 要不要跑全面檢測由 Yolin 決定，Session 不自己跑。

**2-5 文件修改**（定位用條文名稱，不要信行號）：
1. `CLAUDE.md` 第 7 條「26 支測試全綠」：保留全跑的意思，但寫精確——「`npm test`（26 支，不含突變）全綠＋`checkmutations`」；補一句「只改文件的 commit 跑 `doctest`＋`copytest` 即可；全面檢測由 Yolin 指定」。這一條以外不動，檔尾指向段不動。
2. `README.md`：`npm test` 的說明改成「全部 26 支測試（不含突變）」；另列 `npm run mutationtest`（會暫時改寫原始碼，跑的時候不要同時編輯）。
3. STATUS 補遺第 10 條：改成「`npm test`＝26 支、不含突變；`mutationtest` 是獨立指令」。
4. STATUS 交接節你自己寫的那段「跟 `CLAUDE.md` 第 7 條不再衝突」：改成現在的事實——本 App 規定每版全跑，與共用 §5.7 不衝突，理由是 7.5 分鐘與結構。
5. STATUS「開發流程慣例」第 5 條、工作慣例第 11 條、`CLAUDE.md` 第 6 條裡的「平常只跑受影響的測試」：**這幾句現在與本 App 的實際規定不符，改掉**（改成「每版跑什麼見工作慣例第 15 條」之類）。原規格說它們「已一致，不動」，那是建立在有挑選器的前提上，前提沒了。
6. 工作慣例第 15 條：照 2-2 改寫。第 17 條「全面檢測怎麼跑」照 2-3 對齊。

## 3. 測試要求

紀律照舊。這一批新增的程式只有 `scripts/sincefull.mjs`，斷言放進 `doctest`（它本來就守「文件宣稱的對得上程式」，而且每版都跑）：

| # | 斷言 | 前置／對照組 | 突變（用你 v0.36.0 補強的機制，指定失敗的一定是這一條） |
|---|---|---|---|
| D1 | STATUS 有「上次全面檢測」「上次突變整套」兩行，而且 `sincefull` 的解析器讀得出日期、版本、條數 | 兩段式：先斷言那兩行存在，再斷言解析結果 | 把解析的 regex 改壞 |
| D2 | 解析器遇到格式對不上的輸入 → 丟錯 | 對照組：餵一行故意寫壞的，必須丟錯而不是回傳 0 | 讓解析失敗時回傳 0 天 |
| D3 | 「M 條從未整套跑過」＝突變實際總條數 − STATUS 記的上次整套條數，而且 ≥ 0 | 總條數從 `mutationtest.mjs` 數，不寫死 | 把減數寫死 |
| D4 | `package.json` 的 `test` 鏈裡**沒有** `mutationtest`，而 `mutationtest` 這個 npm script 仍然存在 | 對照組：餵一條含 `mutationtest` 的假鏈字串 → 這條判斷式要判成不合格 | 判斷式改成永遠通過 |

這一版自己跑什麼：照新規定——改到了 `scripts/`、`package.json`，不是只改文件，所以 `npm test` 全跑＋`checkmutations`＋`npm run mutationtest -- --only` 這四條新突變。

## 4. 你另外回報的兩件

1. **`copytest`、`edutest` 引用整個 `js/` 根目錄**，以及**目錄引用 `js/views/` 的是 6 支不是 5 支**（多了 `racetest`）：不做挑選器之後這兩件不再需要裁決。你「根目錄引用照樣挑中、但不算認領」的處理方向是對的——請把這兩個事實連同 T10 唯一的真實候選是 `js/timeline.js`，記在你保留的那個 patch 旁邊的說明裡，日後若重啟挑選器用得上。
2. **原規格 §10 的第二步**（`mutationtest --changed`、替舊突變補「失敗的一定要是哪一條」）：跟著重新評估。`--changed` 在「受影響 ≈ 全部」的 App 裡同樣省不到多少，**不做**。替舊的 348 條補指定仍然值得做，而且現在多了一個更迫切的理由：261 條從未整套跑過。統籌者的建議是下一次 Yolin 叫全面檢測時，整套突變跑一次、同時分批補指定；這要 Yolin 點頭，不在這一批。
