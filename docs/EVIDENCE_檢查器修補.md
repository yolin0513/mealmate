## F8：build-recipes、build-foods 資料不見、壞掉、變少時停下（2026-09-24）

**改了什麼**
- 寫檔前先整體檢查。只要有一條問題，就印「✗ 沒有寫檔：」並逐條點名（哪一道、哪一個欄位、哪一項營養素、哪一個類別），回 1，一個檔都不寫。
- 檢查過了才寫 `.tmp`，再 rename 換上。

**build-recipes 在這些情況停下**
- 輸入缺了哪一個就點名哪一個：`data/recipes`、`foods.json`、`aliases.json`、`foodtags.json`。
- 產出 0 道。
- 上一版有、這次沒有的食譜，逐道點名。真的要刪就加 `--allow-shrink`。
- 上一版的 `recipes.json` 讀不出來。

**build-foods 在這些情況停下**
- 原始資料缺了（`data/raw/` 裡沒有，也走同一個 `stop()`）。
- 原始資料 0 列。
- 6 個必要欄位中任何一個，一列都找不到。
- 原始 JSON 壞掉（點名檔名）。
- 轉出 0 種食材。
- 某項營養素，一種食材都沒有值。
- 上一版有的類別整個不見。
- 食材變少（真的要刪就加 `--allow-shrink`）。

這些檢查排在類別覆寫表之前，不會再被「覆寫表的編號找不到」碰巧擋下。

**寫檔那一步（`writeAtomically`，補充說明四）**
- 只清自己寫出來的暫存檔。寫都沒寫成的時候不碰它（例如那個位置本來就有同名資料夾、或被防毒鎖住），並點名那個位置。
- 清理本身失敗也不中斷：一起點名「暫存檔刪不掉、留在原地」，照樣走 `stop()`。

**真實資料照常放行**：build-foods 產出 2,151 種，除了 `generatedAt` 一模一樣；build-recipes 產出 248 道。

### 驗法

指令：`node --max-old-space-size=4096 scripts/buildguard-verify.mjs --rev <commit>`。
- 在 repo 外的拋棄式 worktree 跑，原始資料用複本。
- 母體＝每一個單位 × 每一種情境，寫成迴圈。
- 一格要四件事都成立才算擋：
  1. 回傳非 0。
  2. **錯誤訊息的位置**（stderr 從「✗」那一行起）點名這個單位。食譜 id 要對邊界，`r-foo` 不能被 `r-foo-veg` 湊到。
  3. 輸出檔雜湊沒變，也沒留下暫存檔。
  4. 沒有吐出未處理例外的堆疊。
- 回非 0 但沒點名，算碰巧擋下，也就是算沒擋。
- 跑矩陣之前先跑判準的對照組，兩個方向共 10 種：只出現在正常進度訊息裡要判「不算」，出現在錯誤訊息裡要判「算」；還有前後綴湊到、只有堆疊沒有「✗」、比對模式的擷取。對照組不對就不往下跑。
- 兩份結果比對前，先用 `--compare <舊 log> <新 log>` 斷言兩邊每一組抽到的格數相同而且大於 0。
- 每一組也對預期數量：食譜檔數要等於那個版本 `recipes.json` 的道數；類別數要每一個都在原始資料裡找得到。

### 三段證據

以 2026-09-24 補充說明四之後的驗法為準，共 789 格：食譜 248 道 × 3 種情境＋整體 4 格；食材欄位 6 格、營養素 12 格、類別 18 格、整體 5 格。

**1. 舊版真的是舊的**：驗法先印兩支 build 的 sha，以及新函式在不在。

| 版本 | build-recipes | build-foods | 新函式 |
|---|---|---|---|
| `217db3f`（F8 之前） | `d2dc03102aa9` | `3fb33ea4e1e8` | 都沒有 |
| `f0d05bc`（F8，補充說明四之前） | `874d44c902ac` | `89290ed389a9` | 有檢查，沒有 `writeAtomically` |
| `4b2687f`（補充說明四之後） | `ed082f150a20` | `df752ed20e09` | 都有 |

三版的基準（什麼都不改）都放行。

**關於 `4b2687f`**：矩陣當時是對本機 commit `ed05d1c` 跑的。那個 commit 和下一個 docs commit 都沒推出去過；推送閘門的自查擋下了驗法裡一條合成樣本（寫成磁碟機代號開頭的假路徑），Yolin 2026-09-24 核准把這兩個本機 commit 併成 `4b2687f`（理由見 STATUS 常設規則補遺第 19 條）。**兩支 build 的 sha 不變**（`ed082f150a20`／`df752ed20e09`），證據指的是同一份程式；併之前與併之後的樹雜湊逐位元組相同。`ed05d1c` 跟 `4b2687f` 唯一的程式差別是那一條對照組樣本，改成不帶磁碟機代號的路徑，判準和結果都不變。`--compare` 兩兩比對，母體都相同（789 對 789）。

**2. 舊版沒擋的**

`217db3f`：擋 496、**沒擋 293**，其中碰巧擋下 8 格。
- **食譜**
  - 刪掉一道的 248 格全部照寫，`recipes.json` 就少一道。
  - 資料夾清空照寫，寫成 0 道。
  - 資料夾不存在、foods.json 不存在：只丟 ENOENT 堆疊。
  - 內容清空、欄位打錯這兩組共 496 格，本來就擋。
- **食材**
  - 欄位改名 6 格、營養素整項不見 12 格、類別整類不見 18 格全部沒擋，多數照寫。
  - 整合編號改名、空陣列、只給前 5%、某一類整類不見，都是被「類別覆寫表的編號找不到」碰巧擋下。
  - JSON 壞掉是 SyntaxError 堆疊，沒點名檔名。
  - 原始資料資料夾不存在：理由印了，但不在「✗」之後，照新判準算沒擋。
- **暫存檔的位置被資料夾佔住**：舊版不寫暫存檔、直接寫輸出檔，這一格對它不構成寫檔失敗。照判準算沒擋，但不代表舊版在這裡有洞。

`f0d05bc`（F8 的第一版）：**沒擋 3**，3 格都是碰巧擋下。
- **暫存檔的位置被資料夾佔住**，兩支都中：寫不進去之後，清理程式去刪那個資料夾、刪不掉，在 catch 裡再丟一次例外（`ERR_FS_EISDIR`）。吐出來的是堆疊，不是設計好的點名。**跟統籌者在 JLPT 造出來的是同一個問題。**
- **build-foods 找不到原始資料**：理由印在 stderr，但不在「✗」之後。
- 原本的判準比對整份 stderr，所以這一格被算成擋下。改成只在錯誤訊息的位置比對之後，它被重新歸成沒擋，就差這 1 格：正常的進度訊息印在 stdout，原本的判準本來就不看 stdout。

**3. 新版全擋**：`ed05d1c`（併入 `4b2687f`，build 的 sha 相同）789 格全部擋下，0 格碰巧擋下，`exit=0`。

## 跳脫掃描的母體擴到所有腳本（2026-09-24，補充說明四）

**以前**：gatescan 的 `shell-regex`（grep／sed 樣式含反斜線、寫在 shell 指令列上）只掃 TARGETS 那三支。

**現在**
- 母體：整棵樹走一遍，不走 `.git`、`node_modules`、`.logs`。凡是腳本副檔名的檔都算，加上 `package.json`。
- 孤兒：拿 `git ls-files` 的追蹤清單核對。git 有追蹤、目錄走訪卻沒走到的腳本要報出來；取不到清單就停。
- 登記的例外 2 條，都在 `scripts/mutationtest.mjs`，是突變的說明字串與替換字串。登記了卻沒用到算失敗。

**實跑**：真實 repo 走了 75 支腳本（不含 TARGETS 三支），命中 2 處，都是上面登記的例外，其餘 0 命中。

**常設**：doctest G6-1…G6-4。
- G6-1：`tools/` 底下有壞樣式，要點名那一行。
- G6-2：被追蹤卻沒走到的腳本，要報孤兒。
- G6-3：取不到追蹤清單，要判成檢查器壞了。
- G6-4：真實 repo 至少走 50 支。
- 突變 4 條（不跑跳脫掃描、只走 `scripts/`、不做孤兒核對、取不到清單就當成沒有孤兒），全部紅在指定的斷言。
