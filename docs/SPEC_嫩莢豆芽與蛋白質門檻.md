# SPEC_嫩莢豆芽與蛋白質門檻 — 嫩莢類與豆芽歸蔬菜；算不算蛋白質來源改看每份吃到幾克

> 狀態：已執行（2026-09-19、mealmate-v0.37.0；另見 `docs/SPEC_嫩莢豆芽與蛋白質門檻_裁決一.md`）
> 規劃：Fable 5.1 統籌 Session，2026-09-19。決策都來自 Yolin 2026-09-19 的原話（§9）。事實依據：兩個 Opus 勘查員 2026-09-19 的唯讀實查（HEAD 當時是 `b98f271`；行號以你現在讀到的為準）。

## 0. 前置條件與順序

1. **全面檢測先結案。** 它如果發現任何紅（測試、突變、假斷言），先處理那個並回報；這份規格排在後面。理由：這份會改排菜結果，兩件事交錯做，出了紅分不清是誰造成的。
2. 這是 App 的改動：照你現行的每版流程（bump、`npm test` 全跑、`checkmutations`、新突變 `--only`、push、線上核對、`sincefull` 兩行）。版本號你定（預期 `mealmate-v0.37.0`）。

## 一句話

把九筆「吃嫩莢的豆類」的食材類別改成蔬菜類、讓豆芽不再因為名稱裡有「黃豆」「黑豆」被當成豆製品；同時替「素食成員每餐一道蛋、豆製品或奶類的菜」加一條通則：**蔬菜類的食材，這道菜每份從它吃到的蛋白質 ≥ 4 克，也算達標**。

## 1. 現況（勘查事實）

- 食材的類別 `cat` 直接抄食藥署的「食品分類」（`scripts/build-foods.mjs`），**沒有任何覆寫層**；手改 `data/foods.json` 會在下次換季重建時被蓋掉。
- `proteinGroupOf`（`js/recipeschema.js`）回 `soy` 有兩條獨立的路：`food.cat === '豆類'`，或名稱命中 `豆腐|豆干|豆皮|豆包|豆漿|百頁|豆豉|毛豆|黃豆|黑豆`。嫩莢類走第一條；**黃豆芽、黑豆芽的類別本來就是蔬菜類，是走第二條（名稱含「黃豆」「黑豆」）才被當成豆製品**。
- `isProteinDish`（`js/planner.js`）：蛋類→egg、乳品類→dairy、`proteinGroupOf==='soy'`→soy；門檻 `VEG_PROTEIN_MIN_GRAMS = 15` 是**這樣食材每人的克數**（不是蛋白質克數），任一食材達標即可、不累加；跳過 `pantry`、沒有 `food`、`grams<=0` 的食材。
- `cat` 在全 App 被 12 處讀到，勘查員逐處查過。嫩莢類從豆類改成蔬菜類，**會變的只有**：蛋白質分組與達標（想要的）、買菜清單分區從「豆製品蛋奶」變「蔬菜」（更對）、新增食譜畫面的類別小字（更對）、以及 `js/units.js` 的 `COUNT_UNIT_BY_CAT`——蔬菜類會拿單位重當預設填寫單位「個」（**不想要的副作用**，見 R5）。**不變的**：保存天數（豆類與蔬菜類都是 3 天）、營養估算（不讀 `cat`）、葷素判定、加工判定、主角食材規則、冷凍措辭。
- `proteinGroupOf` 的回傳值只被三處讀：`validateRecipe`（寫進 `proteins`／`vegProteins`／`meatProteins`）、`isProteinDish`、主菜的蛋白質輪替。畫面層沒有任何一處讀 `proteins`。「同一樣主角食材三天內」走的是 `starFoods`，與它無關。
- 每份吃到的蛋白質（勘查員從內建食譜算的）：涼拌四季豆 1.27、乾煸四季豆 1.70、蒜炒豌豆莢 1.81、涼拌豆芽菜（綠豆芽）1.73、**韓式涼拌黃豆芽 5.30**、毛豆玉米炒飯 5.47；對照：皮蛋豆腐 7.35、紅燒豆腐 12.75、芹菜炒豆干 9.65、九層塔煎蛋 7.94。每 100 克：敏豆莢 1.7、豌豆莢 2.9、綠豆芽 2.3、黃豆芽 5.3、黑豆芽 6.6、豌豆芽 4.0。
- 為什麼門檻不能用「每 100 克」：實測把「每 100 克 ≥ 3–7 克」的通則套到內建食譜，會掃到乾香菇（20.9）、麻醬（20.8）、麵腸、乾麵條，連**白飯**（7.0）都會讓每一餐自動達標。乾貨不含水，數字很高但一道菜只用幾克。
- 目前「只靠芽、莢、豆仁達標」的內建食譜有 5 道：涼拌四季豆、乾煸四季豆（素版）、蒜炒豌豆莢、韓式涼拌黃豆芽、毛豆玉米炒飯。
- `plannertest` 裡這條規則的統計（約 697–757 行）：三種家庭 × 8 組種子 × 連排 3 週，母體 `on.meals >= 300`；門檻 `LIMIT = { 有蛋奶素: [0.15, 0.05], 有全素: [0.3, 0.2], 全家全素: [0.2, 0.1] }`；v0.33.0 實測 0%／9%／5%。v0.36.0 之後的實測值統籌者沒有，以你重量的為準。**沒有任何一條突變守著 `proteinGroupOf` 的豆類分支。**

## 2. 目標與非目標

**目標**：G1 Yolin 點名的食材在類別上歸蔬菜，而且換季重建後不會跑回去；G2 四季豆、豌豆莢的菜不再被當成蛋豆奶達標；G3 蛋白質真的多的蔬菜菜（黃豆芽）照樣算達標——判準是含量，不是名稱或類別；G4 既有的達標判定（豆腐、豆干、蛋、奶）一條都不變。

**非目標**：不動毛豆、毛豆仁、豌豆仁、皇帝豆（萊豆仁）、黃豆、紅豆、綠豆、豆漿的類別或判定；不動「每人 15 克食材」那條既有門檻（現在靠它達標的味噌豆腐湯、起司焗南瓜、濃湯不在這次範圍——那是另一個問題，不夾帶）；不動蛋白質輪替的規則；不新增別名（「長豆」「扁豆」「四角豆」目前在別名表查不到，這次不補）；不新增食譜；不新增任何畫面元素。

- **R2 蔬菜類的食材不走名稱規則。** `proteinGroupOf`：`cat === '蔬菜類'` 的食材不回 `soy`（不管名稱裡有沒有「黃豆」「黑豆」）。請先列出蔬菜類裡名稱會命中那條 regex 的**全部**食材寫進回報（勘查員看到的是黃豆芽、黑豆芽；有別的就列出來，不要只處理已知的兩筆）。
- **R3 蔬菜蛋白質通則。** `isProteinDish` 新增一條路：食材 `cat === '蔬菜類'`，而且每份吃到的蛋白質 ≥ 4 克 → 這道菜算達標，種類記成一個新值（名稱你定，例如 `vegprotein`）。其餘條件與現行完全一致：選軌方式、份數取法、跳過 `pantry`／沒有 `food`／`grams<=0`、任一食材達標即可、**不累加**多樣食材。這樣食材的蛋白質是空值 → 不算（不要當成 0 以外的任何東西，也不要丟錯）。
- **R4 既有的路不動。** 蛋類、乳品類、`soy` 三條路與 `VEG_PROTEIN_MIN_GRAMS = 15` 原樣保留。改完之後，現在算達標的內建食譜裡，**只有**涼拌四季豆、乾煸四季豆（素版）、蒜炒豌豆莢三道變成不達標；韓式涼拌黃豆芽繼續達標（改走 R3）；毛豆玉米炒飯不變。實際結果與這句話不符就回報，不要調門檻去湊。
- **R5 補採買單位，堵住副作用。** 九筆裡沒有 `buyUnits` 的（勘查員看到的是豌豆莢、高山大豌豆莢、甜豌豆莢、豇豆(莢)、鵲豆莢；翼豆、粉豆莢、冷凍菜豆(莢)沒有單位重，請實查）改成蔬菜類之後，新增食譜的預設填寫單位會變成「個」（「1 個＝25 克的豌豆莢」）。在 `data/units.json` 補上合理的採買單位，比照四季豆現有的「把／200 g」；**你沒把握的就讓它用克，不要給「個」**。每一筆最後用什麼單位、依據是什麼，寫進回報。
- **R6 文案要誠實。** 達標的理由句（`js/planner.js`「○○這一餐吃得到的蛋、豆製品或奶類的菜」）與本週頁那張卡（「這幾餐排不到蛋、豆製品或奶類的菜給○○」）：一道靠 R3 達標的黃豆芽菜，照 Yolin 的分類是蔬菜，說它是「豆製品的菜」不實。用**最小的改動**讓它誠實——例如靠 R3 達標時理由句另用一句。文案不得用 `scripts/copyrules.mjs` 的禁用詞；`CLAUDE.md` 第 5 條字面上還禁「建議」「應該」等單字，雖然實際的檢查只擋複合詞，這次的新文案請兩邊都避開。改了哪幾句、原文與新文，寫進回報。
- **R7 重建。** `npm run build-foods` → `npm run build-recipes`。三道受影響食譜的 `proteins`／`vegProteins` 會變（涼拌四季豆、蒜炒豌豆莢變成空陣列；乾煸四季豆剩 `pork`），韓式涼拌黃豆芽的 `proteins` 也會變成空陣列（它不再是 `soy`；達標改由 R3 在排菜時判定，不寫進 `proteins`）。
- **R8 統計門檻重量，不照抄。** `plannertest` 那一節用現行的 8 組種子 × 3 週重跑，把**改動前**與**改動後**三種家庭的實測值並列寫進回報；門檻照補遺第 12 條重設（照最差的一組留約 5 個百分點），對照組（開關關著時）的下限同樣重量。如果「有全素」或「全家全素」排不到的比例明顯上升，**照實報出來**——那是 `docs/SPEC_全素蛋白質食譜補充.md` 要解的問題變得更迫切，不是這份規格要用放寬門檻蓋掉的事。

## 8. 附帶一項：`sincefull` 的兩行要帶上實測耗時
