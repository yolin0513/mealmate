# SPEC 草稿：新增食譜找食材的排序（生鮮優先於加工品）

> 狀態：**草稿，尚未動工**。2026-09-18 交接整理時寫下，等 Yolin 決定要不要做（見 `STATUS.md`「等 Yolin 回覆」）。

## 為什麼

新增食譜的食材框打「豬肉」，2026-09-18 實測前 8 筆是：
山豬肉片、冷凍豬肉湯圓、冷凍豬肉水餃、冷凍豬肉韭菜水餃、冷凍豬肉蟹黃水餃、冷凍豬肉熟水餃、冷凍豬肉餛飩、豬肉鍋貼。
「雞肉」「牛肉」也一樣，前幾筆多半是水餃、香腸、火腿、泡麵。
原因：`foods.searchFoods` 的順序是「精確命中 → 名稱包含 → 俗名包含」，名稱包含那一段照資料庫原本的順序；
生鮮的豬肉部位名稱是「豬大里肌」「豬後腿肉」，字面上不含「豬肉」，反而排不到前面。

## 要做的事（只動新增食譜畫面用的 `collapse: true` 那條路）

1. 「名稱包含」與「俗名包含」兩段，各自照類別排序：生鮮類（肉類、魚貝類、蔬菜類、菇類、水果類、蛋類、豆類、穀物類、澱粉類、乳品類）在前，
   調味料、加工調理食品、糕餅點心、飲料在後；同一群裡維持原順序。精確命中永遠第一。
2. 打「豬肉」時補一條規則的話要小心：不要用子字串去猜（「豬」會撈到馬齒莧的俗名「豬母乳」，見 `foods.js` 開頭的註解）。
   建議只做排序，不做同義詞擴充；要擴充就加進 `data/aliases.json`（例如「豬肉」→ 豬後腿肉），由 `aliastest` 守。

## 驗收

· `unittest`：搜「豬肉」「雞肉」「牛肉」前 3 筆都是肉類或俗名命中，加工品排在後面；對照組：`collapse: false`（其他地方的搜尋）順序不變。
· `recipeviewtest` 既有的單一食材框測試全綠。
· 新斷言各自有突變驗紅。
